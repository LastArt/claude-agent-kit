# Инструкция

Claude Agent Kit — набор настроек для Claude Code: мультиагентный конвейер из девяти
агентов, оркестраторный промт, хук проверки синтаксиса, шаблоны артефактов и команды
разворачивания. Устанавливается один раз и доступен в любом проекте.

## Структура

```
claude-agent-kit/
├── install.bat              установка двойным щелчком (Windows)
├── install.ps1              установщик для Windows (его и вызывает .bat)
├── install.sh               установщик для Linux/macOS
├── README.md                описание проекта
├── CHANGELOG.md             журнал изменений
├── SETUP.md                 этот файл
└── .claude/                 набор файлов, копируемый в проекты
    ├── VERSION              версия набора — единственное место, где она хранится
    ├── PROJECT_PROFILE.md   специфика проекта: команды, пути, стиль
    ├── PROJECT_PROFILE.template.md  чистый шаблон профиля (в проекты уезжает он)
    ├── ORCHESTRATOR_PROMPT.md
    ├── CUSTOMIZE.md         настройка развёрнутого экземпляра
    ├── CLAUDE.md            про разработку самого набора (в проекты НЕ копируется)
    ├── WELCOME.md           текст окна приветствия — правится свободно
    ├── settings.json        права доступа и регистрация хуков
    ├── assets/logo.txt      логотип текстом — замените файл, чтобы сменить знак
    ├── assets/logo-mini.txt узкий вариант знака для терминала
    ├── commands/            все команды (шесть из них установщик делает глобальными)
    ├── hooks/               banner.mjs — приветствие и версия
    │                        check-syntax.mjs — проверка после правки файла
    │                        write-manifest.mjs — реестр установленных файлов
    │                        update.mjs / uninstall.mjs — обновление и удаление набора
    │                        verify.mjs — прогон проверок проекта, пишет artifacts/VERIFY.json
    │                        gate.mjs — Stop-гейт: не даёт закончить ход с красными проверками
    │                        events.mjs — журнал событий artifacts/events.jsonl (только дописывание)
    │                        stubs.mjs — раскладывает заглушки рабочих файлов
    │                        make-guide.mjs, git-status.mjs, stats.mjs, map.mjs
    ├── agents/              девять субагентов
    ├── assets/stubs/        эталонные заглушки PLAN/REVIEW/SECURITY/FAQ и INDEX разведок
    └── artifacts/           PLAN.md, REVIEW.md, SECURITY.md, FAQ_TEMPLATE.md
                             (рабочие файлы: в исходниках набора их нет, их кладёт stubs.mjs)
```

Единственный источник команд — `.claude/commands/`. Поэтому в развёрнутом проекте видны все
команды сразу, а установщик просто копирует шесть из них (`cckit_new-project`, `cckit_install`,
`cckit_update`, `cckit_uninstall`, `cckit_help`, `cckit_get_instruction`) в домашнюю папку,
чтобы они работали и вне проектов.

Часть файлов принадлежит только этому репозиторию и никогда не уезжает к пользователям:
`CLAUDE.md` (инструкции по разработке набора) и `settings.local.json` (разрешения конкретной
машины). Установщики удаляют их из копии, команды разворачивания — не копируют.

Отдельная история у профиля: `PROJECT_PROFILE.md` в этом репозитории описывает **сам набор**,
поэтому в мастер-копию и в проекты уезжает `PROJECT_PROFILE.template.md` — чистый шаблон,
который потом заполняет `/cckit_research`. Установщик подменяет один другим автоматически.

## Установка

Установщик копирует набор в домашнюю папку текущего пользователя:

- `~/.claude/agent-kit/` — файлы набора (без `settings.local.json`: это локальные разрешения
  вашей машины, в чужие проекты им нельзя);
- `~/.claude/commands/` — команды `/cckit_new-project`, `/cckit_install`, `/cckit_update`,
  `/cckit_uninstall`, `/cckit_help`, `/cckit_get_instruction`.

**Windows:**
```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1
```

**Linux / macOS:**
```bash
bash install.sh
```

Установщик печатает, что установил, и проверяет наличие Node.js — на нём работает хук проверки
синтаксиса.

**После установки полностью перезапустите VS Code.** Команды читаются один раз при старте;
`/clear` их не перечитывает. Это самая частая причина «команды не появились».

## Проверка, что всё работает

В папке проекта с развёрнутым набором:

```bash
node .claude/hooks/check-syntax.mjs --selftest
```

Команда покажет, какие языки проверяются на этой машине. Блокирующая проверка всегда доступна
для JS и JSON (встроенный парсер Node — `node --check` и `JSON.parse`), для Python — если
в системе есть настоящий интерпретатор. Для TypeScript и JSX глубокого разбора нет — только
проверка баланса скобок: полноценный парсер намеренно не тянем, чтобы набор работал сразу
после распаковки, без `npm install`.

Из папки набора запускается только установщик. Сами команды (`/cckit_new-project` и другие)
выполняются в папках ваших проектов, а не в папке набора — после установки она для работы
не нужна и может быть удалена. Команды доступны глобально.

## Разворачивание в проекте

### Новый проект

Выполните (из любой папки):

```
/cckit_new-project book-tracker
```

Команда создаёт папку `cckit-projects/book-tracker` в вашей домашней директории — с настроенным
набором и файлом `IDEA.md` для замысла (корневой `CLAUDE.md` не создаётся: если он понадобится,
его соберёт `/cckit_research` из разведки репозитория). Все проекты, созданные так, собираются
в одном месте (`~/cckit-projects/`).

Если хотите создать проект в конкретной папке — откройте Claude Code в ней и выполните
`/cckit_new-project` без аргумента: набор развернётся в текущую папку, имя возьмётся из её названия.

Затем: опишите замысел в `IDEA.md`, выполните `/cckit_research`, перезапустите Claude Code.

### Существующий проект

Откройте Claude Code в папке проекта и выполните:

```
/cckit_install
```

Команда добавляет только недостающие файлы. Уже существующие (`settings.json`, агенты,
`PROJECT_PROFILE.md`, `PLAN.md` и другие) не изменяются; их список выводится в конце.

Затем: выполните `/cckit_research`, перезапустите Claude Code.

## Работа над задачами

После разворачивания и `/cckit_research` задачи ставятся командами:

- `/cckit_feature <задача>` — полный конвейер: исследование → план → подтверждение →
  реализация → ревью → подтверждение. Для новых функций и заметных изменений.
- `/cckit_quick <задача>` — короткий путь: план → реализация → быстрая проверка, без разведки.
  Для мелких, понятных правок.

Когда нужен только один шаг, агента можно вызвать отдельно: `/cckit_explore`, `/cckit_plan`,
`/cckit_audit`, `/cckit_implement`, `/cckit_review`, `/cckit_docs`, `/cckit_faq`, `/cckit_release`,
`/cckit_commits`. Каждая такая команда запускает ровно одного агента и останавливается.

Справка по всем командам — `/cckit_help`. Она собирает список из файлов набора, поэтому не
устаревает.

## Окно приветствия

При первом разворачивании в проекте и по команде `/cckit_welcome` набор показывает окно
приветствия: логотип, версию, число агентов и с чего начать.

Логотип там **текстовый**, и это вынужденно: окно чата Claude Code не отображает локальные
картинки — markdown вида `![логотип](assets/logo.png)` показывается в нём сырой строкой
(проверено). PNG используется там, где картинки работают: в шапке README на GitHub и в
предпросмотре markdown внутри VS Code.

Текст правится в `.claude/WELCOME.md` — обычный markdown с подстановками `{{LOGO}}`,
`{{VERSION}}`, `{{AGENTS}}`, `{{COMMANDS}}`, `{{PROFILE}}`, `{{NEXT}}`. Посмотреть, что получится:

```bash
node .claude/hooks/banner.mjs --welcome
```

### Свой логотип

Два файла, оба правятся без единой строчки кода:

- `.claude/assets/logo.txt` — полный знак;
- `.claude/assets/logo-mini.txt` — узкий вариант для терминала (необязателен).

В приветствии логотип уходит в блок кода с горизонтальной прокруткой, поэтому ширина там
не ограничена и всегда показывается полный знак. А вот в терминале длинные строки
переносятся и рисунок рассыпается, поэтому там знак выбирается по ширине окна:

1. помещается полный — показывается он;
2. не помещается — берётся `logo-mini.txt`;
3. этого файла нет — из полного знака вырезается первый блок (до пустой строки)
   и подписывается названием;
4. рисунков нет вовсе — остаётся одна строка с названием.

Установщик передаёт баннеру реальную ширину окна (флаг `--cols`), поэтому полный знак виден,
если окно достаточно широкое; в узком окне автоматически берётся `logo-mini.txt`.

## Версия набора

Версия хранится в `.claude/VERSION` — одной строкой, больше нигде. Посмотреть версию
развёрнутого в проекте набора:

```bash
node .claude/hooks/banner.mjs
```

Та же строка печатается установщиком и при старте сессии (коротким вариантом). Так можно
понять, не отстал ли набор в конкретном проекте от свежего — и при необходимости обновить его
командой `/cckit_update`.

## Настройка под проект

Вся специфика проекта хранится в одном файле — `.claude/PROJECT_PROFILE.md`: команды сборки,
тестов и линтера, расположение модулей, конвенции стиля. Агенты читают этот файл, поэтому
остаются универсальными.

Команда `/cckit_research` заполняет профиль автоматически: при наличии кода она изучает
репозиторий, при пустом проекте — опирается на описание из `IDEA.md`, помечая недостающее
как `TODO`.

## Настройка поведения в проекте

Папка `.claude/` каждого проекта — независимая копия. Её файлы можно править: это меняет
поведение конвейера только в этом проекте и не затрагивает установленный набор. Полный
перечень настроек — в `.claude/CUSTOMIZE.md`.

По умолчанию Claude Code запрашивает подтверждение перед каждой правкой файла.
Переключить на автоматический приём правок можно прямо в сессии клавишами `Shift+Tab`
(без правки файлов — мгновенно). Чтобы проект стартовал в этом режиме **по умолчанию**,
добавьте `"defaultMode": "acceptEdits"` в раздел `permissions` файла `.claude/settings.json`.
Запреты на доступ к секретам (`.env`, ключи) действуют в любом режиме.

## Перенос на другой компьютер

1. Скопируйте папку `claude-agent-kit/` — через систему контроля версий, облако или носитель.
2. Запустите установщик (`install.ps1` или `install.sh`).
3. Перезапустите Claude Code.

## Обновление

Набор распространяется через GitHub, поэтому обновление идёт по слоям:

1. **Исходник** — в папке клона запустите `update.bat` (Windows) или `bash update.sh`
   (Linux/macOS): скрипт делает `git pull` и сразу переустанавливает `~/.claude/agent-kit/`.
   Без git (скачан ZIP) — скачайте свежий ZIP, распакуйте поверх и запустите установщик.
2. **Проекты** — в каждом развёрнутом проекте выполните `/cckit_update`. Он обновляет механизм
   (агентов, хуки, команды) до версии из `~/.claude/agent-kit/`, но бережёт живые файлы
   (`settings.json`, `PROJECT_PROFILE.md`, `PLAN.md`/`REVIEW.md`, история) и ваши правки:
   что меняли сами — не перезаписывает молча, а показывает и спрашивает. Устаревшие файлы
   прошлых версий предлагает удалить.

Разница с `/cckit_install`: install только **добавляет недостающее** и никогда не трогает
существующее — он для первого разворачивания, а не для обновления. Механизм обновляет именно
`/cckit_update`.

Разработчику самого набора (у кого папка — источник, а не клон) отдельный `git pull` не нужен:
достаточно поправить файлы и запустить установщик.

Убрать набор из проекта — `/cckit_uninstall`: снять только служебные файлы (сохранив историю
задач) или всё целиком. Удаляет строго свои файлы по реестру `.claude/.cckit-manifest.json`,
чужого и вашего кода не трогает.
