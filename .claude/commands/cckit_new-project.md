Разверни Claude Agent Kit в новый проект.

Аргумент (имя проекта, необязателен): $ARGUMENTS

## Где взять файлы кита (источник)

Проверь по порядку и возьми ПЕРВЫЙ существующий:

1. `~/.claude/agent-kit/` — установленный мастер-кит (на Windows
   `%USERPROFILE%\.claude\agent-kit`). Домашнюю папку определи сам, не хардкодь чужой путь.
2. `.claude/` **текущей папки** — если в ней есть `agents/` и `ORCHESTRATOR_PROMPT.md`.
   Это случай «кит только что распакован, установщик ещё не запускали».

Если не нашлось ни того, ни другого — остановись и скажи: «Кит не найден. Запусти
`install.ps1` (Windows) или `install.sh` (Linux/macOS) из папки набора, затем полностью
перезапусти Claude Code».

## Действуй так

1. **Определи имя и целевую папку:**
   - Аргумент **задан** → `имя = аргумент`; целевая папка = `<домашняя>/cckit-projects/<аргумент>`.
     Создай папку `cckit-projects` в домашней директории, если её ещё нет, затем внутри — папку
     проекта. (Домашняя: Windows `%USERPROFILE%`, Linux/macOS `$HOME`.)
   - Аргумент **пуст** → `имя = имя ТЕКУЩЕЙ папки`; целевая папка = текущая директория
     (место выбрано пользователем — не переноси).
   - Покажи мне имя и **полный путь** целевой папки одной строкой.

2. **Защита (для случая без аргумента):** если целевая = текущая папка и это исходники самого
   набора (в её корне есть одновременно `install.ps1` и `install.sh`) — НЕ разворачивай сюда.
   Остановись и скажи: «Это папка с исходниками набора. Запусти `/cckit_new-project <имя>`
   (проект создастся в `~/cckit-projects/`) или открой Claude Code в папке своего проекта».

3. **Скопируй кит** из найденного источника в `<целевая>/.claude/` — всю структуру
   (`agents/`, `artifacts/FAQ_TEMPLATE.md`, `commands/`, `hooks/`, `settings.json`,
   `ORCHESTRATOR_PROMPT.md`, `PROJECT_PROFILE.md`, `CUSTOMIZE.md`).
   - **НЕ копируй `settings.local.json`** (локальные разрешения чужой машины) и
     **`CLAUDE.md` из папки `.claude/`** (инструкции по разработке самого набора —
     к проекту пользователя отношения не имеют).
   - **НИКОГДА не копируй из мастер-копии** — это память и якоря доверия чужого проекта, а не
     часть набора: `artifacts/VERIFY.json`, `artifacts/VERIFY.lock`, `artifacts/GATE_STATE.json`,
     `artifacts/events.jsonl`, `artifacts/ROADMAP.md`, папки задач `tasks/<id>/` и кэш разведок.
     Из `artifacts/` переносится **только** `FAQ_TEMPLATE.md`, из `tasks/` — **только** указатель
     `ACTIVE`, из `explores/` — **только** `INDEX.md`. Приехавший `VERIFY.lock` сделал бы блок
     проверок «подтверждённым» в проекте, где человек «да» с клавиатуры не вводил: подтверждение —
     это совпадение хеша набора команд, ни к машине, ни к проекту оно не привязано.
   - **ADDITIVE:** уже существующие в целевой папке файлы НЕ перезаписывай — пропусти и в конце
     громко перечисли пропущенное.

4. **Профиль проекта.** В источнике есть `PROJECT_PROFILE.template.md`? Значит, лежащий рядом
   `PROJECT_PROFILE.md` — это заполненный профиль чужого проекта: **не копируй его**, вместо
   этого положи в целевую папку шаблон под именем `PROJECT_PROFILE.md`, а сам файл
   `PROJECT_PROFILE.template.md` в проект не тащи. Шаблона нет — копируй `PROJECT_PROFILE.md`
   как есть (это уже чистый шаблон).
   В получившемся файле подставь `<ИМЯ ПРОЕКТА>` = имя проекта.

5. **Создай в корне проекта файл идеи** (только если его ещё НЕТ). Корневой `CLAUDE.md`
   **не создавай** — если он понадобится, его соберёт `/cckit_research` из разведки репозитория.
   - `IDEA.md` — заголовок `# Идея проекта — <имя>`, ниже **закомментированный** блок-подсказка
     (внутри `<!-- ... -->`) с таким текстом:
     «Удалите этот блок и впишите СВОЙ замысел на его месте (заголовок выше не трогайте).
     Опишите свободным текстом: что за программа, для кого, какую задачу решает, что обязательно
     должно быть, а чего быть не должно — чем подробнее, тем точнее Агент Кит разложит идею на план.
     ⚠️ Не забудьте СОХРАНИТЬ файл (Ctrl+S), потом выполните /cckit_research.»
     Под комментарием — строка-плейсхолдер `_(здесь ваша идея)_`.
     Слово «набор» не используй — только **«Агент Кит»**.

6. **Закрой служебные файлы от репозитория проекта.** Агент Кит и файл идеи — рабочие документы
   на машине человека, а не часть его продукта: в репозиторий едет чистый проект. Допиши в
   `.gitignore` целевого проекта (создай файл, если его нет; если блок уже есть — не дублируй):

   ```
   # Claude Agent Kit — служебные файлы, остаются на этой машине (не в репозитории проекта).
   # Поделиться набором с командой осознанно: /cckit_push-with-me
   .claude/
   # Результаты прогона проверок, подтверждение набора команд, состояние гейта и журнал
   # событий: остаются на этой машине, даже если строка .claude/ выше будет убрана.
   .claude/artifacts/VERIFY.json
   .claude/artifacts/VERIFY.lock
   .claude/artifacts/GATE_STATE.json
   .claude/artifacts/events.jsonl
   # Папки задач: планы, аудиты и ревью этого проекта — рабочие черновики, а не часть
   # продукта. Тоже остаются на этой машине, даже если строка .claude/ выше будет убрана.
   .claude/tasks/
   # Резервные копии папки набора: их кладёт пульт перед раскладкой, внутри — всё то же самое.
   .claude.backup-*/
   # Замысел проекта — внутренний документ для работы с Агентом Китом, не часть продукта.
   IDEA.md
   ```

7. **Запиши реестр установленных файлов.** Выполни `node .claude/hooks/write-manifest.mjs` —
   он создаст `.claude/.cckit-manifest.json`, по которому потом работает `/cckit_uninstall`
   (аккуратное удаление кита без вреда чужим файлам). `node` не найден — пропусти, скажи одной
   строкой, что реестр не создан и удаление по нему будет недоступно.

8. **Шапка.** Выполни `node .claude/hooks/banner.mjs --mini` и вставь полученный markdown
   в начало ответа **как есть** (это логотип + версия + черта). Welcome-простыню (описание ролей,
   таблицу команд, «первый шаг») НЕ показывай — это повтор. `node` не найден — пропусти шапку и
   скажи одной строкой, что без Node хуки работать не будут.

9. **Селф-тест перед отчётом.** Выполни `node .claude/hooks/check-syntax.mjs --selftest` и покажи
   результат одной-двумя строками, оформив эмодзи:
   - ✅ всё зелёно (exit 0, ошибок нет);
   - ❌ тест упал или есть ошибки — назови, что именно;
   - ⚠️ на что обратить внимание (напр.: для языка проекта проверка на этой машине недоступна).

10. **Отчёт** (с эмодзи для наглядности):
   - 📋 Имя проекта: …
   - 📁 Полный путь: …
   - 💾 Источник кита: …
   - что создано / что пропущено — кратко.

   Затем дословно, по шагам:
   «Проект создан. Дальше:
   1️⃣ Открой эту папку в VS Code: File → Open Folder → `<полный путь>` (откроется новое окно).
   2️⃣ Включи расширение **Claude Code** (кнопка **Enable**); при запросе доверия к папке нажми **Trust**.
   3️⃣ Впиши замысел в `IDEA.md` и **сохрани файл** (Ctrl+S).
   4️⃣ В чате выполни `/cckit_research` — Агент Кит изучит идею и разложит её на план
       (посмотреть план: `/cckit_what_plan`).
   После этого ставь задачи: `/cckit_feature <задача>`.»

Ты только раскладываешь кит и заготовки — **прод-код не пишешь**.
