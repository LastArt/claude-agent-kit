# Настройка этого экземпляра

Папка `.claude/` — независимая копия набора, принадлежащая только этому проекту.
Любые правки здесь меняют поведение конвейера **в этом проекте** и не затрагивают
исходный набор на компьютере или в репозитории. Редактируйте свободно.

> **Специфику проекта пишите не здесь, а в `.claude/PROJECT_PROFILE.md`** — команды, пути,
> стиль и запреты живут там, и все агенты читают их именно оттуда. Остальные файлы кита
> (агенты, хуки, промт оркестратора) — это общий механизм: трогайте их, только если хотите
> изменить само поведение конвейера. Кит помнит свои файлы в реестре
> `.claude/.cckit-manifest.json`; если вы правили служебный файл, при удалении
> (`/cckit_uninstall`) кит отдельно спросит про него, а не снесёт молча.

## Частые настройки

| Что нужно | Где править | Как |
|-----------|-------------|-----|
| Авто-принимать правки файлов без подтверждения | `.claude/settings.json` → `permissions` | добавить `"defaultMode": "acceptEdits"` |
| Вернуть подтверждение каждой правки | `.claude/settings.json` → `permissions` | убрать строку `defaultMode` |
| Убрать ненужного помощника | `.claude/agents/` | удалить его `.md`-файл |
| Изменить поведение помощника | `.claude/agents/<имя>.md` | отредактировать текст |
| Сменить модель помощника | `.claude/agents/<имя>.md` | поле `model` во front-matter |
| Разрешить/запретить команду или путь | `.claude/settings.json` → `allow` / `deny` | добавить правило |
| Задать команды и пути проекта | `.claude/PROJECT_PROFILE.md` | заполнить поля |

## Модели помощников

Каждый помощник работает на своей модели — тяжёлая там, где ошибка дорого стоит, полегче
там, где задача простая:

| Помощник | Модель | Почему |
|----------|--------|--------|
| `planner`, `implementer`, `reviewer`, `security-auditor` | `opus` | план, код, поиск багов и аудит безопасности — цена ошибки высокая |
| `explorer`, `documenter`, `changelog-writer`, `commit-organizer` | `sonnet` | поиск, изложение, раскладка правок |
| `faq-writer` | `haiku` | простой текст без кода |

Меняется одной строкой во front-matter агента:

```yaml
---
name: faq-writer
model: sonnet          # было haiku
---
```

Допустимые значения: `opus`, `sonnet`, `haiku`, `inherit` (та же модель, что у основной
сессии). Ошиблись в написании — хук проверки скажет об этом при следующей правке файла.

Стало казаться, что помощник «тупит», — поднимите ему модель. Наоборот, тратит слишком
много на ерунду — опустите. Никаких других файлов при этом трогать не нужно.

## Про авто-приём правок (`acceptEdits`)

По умолчанию Claude Code спрашивает подтверждение перед каждой правкой файла — это
предохранитель. Режим `acceptEdits` его снимает: правки применяются сразу, без вопроса.

**Переключить на время работы — клавишами `Shift+Tab`** прямо в Claude Code. Они циклически
меняют режим (обычный → авто-приём правок → planning) мгновенно, без правки файлов. Для
разового «сейчас хочу без подтверждений» это самый быстрый способ.

Ниже — как задать режим **по умолчанию** (чтобы каждый запуск проекта стартовал в нём).
Файл `settings.json` трогается только для этого.

Включить по умолчанию (правки применяются автоматически с первого запуска):

```json
{
  "permissions": {
    "defaultMode": "acceptEdits",
    "allow": [ ... ],
    "deny": [ ... ]
  }
}
```

Убрать строку `defaultMode` — вернётся подтверждение каждой правки.

Запреты в `deny` (доступ к `.env`, ключам) действуют в любом режиме и переопределяют `allow`.

## Обновление настроек в открытом Claude Code

Файл `settings.json` читается при запуске. После правки полностью перезапустите Claude Code
(команда очистки истории настройки не перечитывает).
