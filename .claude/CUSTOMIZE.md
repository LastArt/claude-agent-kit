# Настройка этого экземпляра

Папка `.claude/` — независимая копия набора, принадлежащая только этому проекту.
Любые правки здесь меняют поведение конвейера **в этом проекте** и не затрагивают
исходный набор на компьютере или в репозитории. Редактируйте свободно.

> **Специфику проекта пишите не здесь, а в `.claude/PROJECT_PROFILE.md`** — команды, пути,
> стиль и запреты живут там, и все агенты читают их именно оттуда. Остальные файлы кита
> (агенты, хуки, промт оркестратора) — это общий механизм: трогайте их, только если хотите
> изменить само поведение конвейера. Кит помнит свои файлы в реестре
> `.claude/.cckit-manifest.json`; если вы правили служебный файл, при удалении
> (`/cckit_uninstall`) кит отдельно спросит про него, а не снесёт молча.

## Частые настройки

| Что нужно | Где править | Как |
|-----------|-------------|-----|
| Авто-принимать правки файлов без подтверждения | `.claude/settings.json` → `permissions` | добавить `"defaultMode": "acceptEdits"` |
| Вернуть подтверждение каждой правки | `.claude/settings.json` → `permissions` | убрать строку `defaultMode` |
| Убрать ненужного помощника | `.claude/agents/` | удалить его `.md`-файл |
| Изменить поведение помощника | `.claude/agents/<имя>.md` | отредактировать текст |
| Сменить модель помощника | `.claude/agents/<имя>.md` | поле `model` во front-matter |
| Разрешить/запретить команду или путь | `.claude/settings.json` → `allow` / `deny` | добавить правило |
| Задать команды и пути проекта | `.claude/PROJECT_PROFILE.md` | заполнить поля |
| Задать проверки, которые гоняет гейт | `.claude/PROJECT_PROFILE.md` → §2, блок `CCKIT:VERIFY` | вписать пары `name` / `cmd` |
| Посмотреть команды блока | где угодно | `node .claude/hooks/verify.mjs --show` |
| Подтвердить блок проверок | **только терминал** | `node .claude/hooks/verify.mjs --accept` |
| Временно отключить гейт | терминал | `node .claude/hooks/gate.mjs --disarm` или `CCKIT_GATE=off` |
| Посмотреть список задач | терминал | `node .claude/hooks/task.mjs list` |

## Модели помощников

Каждый помощник работает на своей модели — тяжёлая там, где ошибка дорого стоит, полегче
там, где задача простая:

| Помощник | Модель | Почему |
|----------|--------|--------|
| `planner`, `implementer`, `reviewer`, `security-auditor` | `opus` | план, код, поиск багов и аудит безопасности — цена ошибки высокая |
| `explorer`, `documenter`, `changelog-writer`, `commit-organizer` | `sonnet` | поиск, изложение, раскладка правок |
| `faq-writer` | `haiku` | простой текст без кода |

Меняется одной строкой во front-matter агента:

```yaml
---
name: faq-writer
model: sonnet          # было haiku
---
```

Допустимые значения: `opus`, `sonnet`, `haiku`, `inherit` (та же модель, что у основной
сессии). Ошиблись в написании — хук проверки скажет об этом при следующей правке файла.

Стало казаться, что помощник «тупит», — поднимите ему модель. Наоборот, тратит слишком
много на ерунду — опустите. Никаких других файлов при этом трогать не нужно.

## Про авто-приём правок (`acceptEdits`)

По умолчанию Claude Code спрашивает подтверждение перед каждой правкой файла — это
предохранитель. Режим `acceptEdits` его снимает: правки применяются сразу, без вопроса.

**Переключить на время работы — клавишами `Shift+Tab`** прямо в Claude Code. Они циклически
меняют режим (обычный → авто-приём правок → planning) мгновенно, без правки файлов. Для
разового «сейчас хочу без подтверждений» это самый быстрый способ.

Ниже — как задать режим **по умолчанию** (чтобы каждый запуск проекта стартовал в нём).
Файл `settings.json` трогается только для этого.

Включить по умолчанию (правки применяются автоматически с первого запуска):

```json
{
  "permissions": {
    "defaultMode": "acceptEdits",
    "allow": [ ... ],
    "deny": [ ... ]
  }
}
```

Убрать строку `defaultMode` — вернётся подтверждение каждой правки.

Запреты в `deny` (доступ к `.env`, ключам) действуют в любом режиме и переопределяют `allow`.

## Задачи

Работа набора разложена по задачам, и у каждой — своя папка `.claude/tasks/<id>/`:
`STATE.md` (состояние конвейера и журнал задачи), `PLAN.md`, `SECURITY.md`, `REVIEW.md`.
Рядом лежит указатель `.claude/tasks/ACTIVE` — одна строка с id той задачи, над которой
идёт работа сейчас. Задачи не затирают друг друга: новая не трогает файлы прошлой.

Папка считается задачей, только если имя имеет вид `ГГГГ-ММ-ДД-имя` (строчная латиница,
цифры и дефис) **и** внутри лежит `STATE.md`. Всё прочее в `.claude/tasks/` читатели
пропускают молча — своя папка с заметками там ничего не сломает.

### Три разных «blocked»

Слово одно, смыслов три, и лежат они в трёх разных файлах:

| Где | Что значит | Отчего наступает |
|-----|-----------|------------------|
| `GATE_STATE.json`, `status: blocked` | **приёмка остановлена** | три красных прогона подряд или подмена набора проверок |
| `STATE.md`, `status: blocked` | **задача остановлена**, дальше решает человек | не сошлись три итерации ревью либо ревью невозможно |
| `REVIEW.md`, `verdict: blocked` | **ревью невозможно** | провести ревью нечем: нет плана, предмет не определить |

Счётчиков тоже два, и они независимы: `review_iterations` в `STATE.md` считает возвраты
на доработку, `attempts` в `GATE_STATE.json` — красные прогоны приёмки. Оба до трёх. Гейт
статус задачи **не меняет** — он пишет своё состояние и одну строку в журнал задачи.

В раундах доработки приёмку гоняют исполнитель и ревьюер, а не гейт: он срабатывает не более
одного раза за задачу.

### Петля доработки и её цена

Ревью с вердиктом `changes_requested` возвращает задачу исполнителю **без вас**, до трёх раз
(режимы A и B; `/cckit_quick` и `/cckit_review` остаются ручными). Считайте расход заранее:
до трёх раундов — это до четырёх запусков `reviewer` и до четырёх `implementer` (оба на opus)
и **порядка восьми** полных прогонов блока `CCKIT:VERIFY`: по одному от исполнителя в каждом
круге (до 4), по одному от ревьюера в каждом раунде доработки (до 3; в первой итерации он
делает `--fresh`, а тот ничего не запускает) и один прогон гейта на первом завершении хода.
В самом наборе блок дешёвый, у вас это может быть `npm test` с бюджетом до 870 секунд
на прогон — включая петлю, вы соглашаетесь на этот расход заранее.

**Продлить круг может только человек.** `review_iterations` не сбрасывается нигде — ни при
возврате в `reviewing`, ни при закрытии задачи. Хотите дать задаче ещё круг — поправьте поле
в `STATE.md` руками: файл закрыт `deny` от агента, но не от вас. Обнулить счётчик иначе можно
только новой задачей (`task.mjs new`), и она намеренно вне `permissions.allow` — несёт
свободный текст названия. Незаметно от вас счётчик этим не обнулить: новая задача заводит
новую папку и переставляет указатель `ACTIVE`, то есть след остаётся в любом случае. Гарантией,
что вас непременно спросят, отсутствие в `allow` при этом **не является** — см. оговорку ниже.

**Что вы делаете руками.** Посмотреть список задач и активную из них —
`node .claude/hooks/task.mjs list`, узнать путь активной — `node .claude/hooks/task.mjs path`.
Обе лежат в `allow` и вопросов не задают. А `new` и `log` в `allow` **намеренно не попадают**:
они несут произвольный текст — название задачи и строку журнала. Обещать, что вас непременно
спросят, мы при этом не можем: см. оговорку ниже, отсутствие в `allow` гарантией не является.

**`STATE.md` — это не `GATE_STATE.json`.** Первый описывает состояние конвейера (какой статус
у задачи, что уже сделано), второй — состояние приёмки (взведён ли гейт, сколько было попыток,
чем кончился прогон). Дублировать одно в другом значило бы завести вторую правду, поэтому
полей приёмки в `STATE.md` нет и не будет.

Причина глубже: **приёмка меряет рабочее дерево, а не задачу.** Дерево одно на все задачи,
проверки из блока `CCKIT:VERIFY` гоняются по нему целиком. Поэтому «зелёная задача»
в `node .claude/hooks/task.mjs list` означает ровно одно: «дерево было зелёным на `<armed_at>`»,
не более.

**Взвод переживает закрытие задачи** — намеренно: приёмка не перестаёт требоваться оттого,
что задачу закрыли. Поэтому `task.mjs close` предупреждает, если гейт остался на задаче
в любом состоянии, кроме `verified`, — в том числе в `blocked`, где человек нужен обязательно.
Снимается взвод двумя способами: зелёным прогоном приёмки (сам) или командой
`node .claude/hooks/gate.mjs --disarm` (вы, из терминала).

**Задачи не путешествуют между проектами.** Механизм — агентов, команды, хуки — `/cckit_update`
обновляет как обновлял. А вот **из трёх папок памяти** (`artifacts/`, `tasks/`, `explores/`)
он с 1.14.0 доносит только заглушки, которые набор и так материализует сам: `tasks/ACTIVE`,
`explores/INDEX.md` и `artifacts/FAQ_TEMPLATE.md`. Ни папок задач, ни файлов приёмки
(`VERIFY.json`, `VERIFY.lock`,
`GATE_STATE.json`), ни журнала `events.jsonl`, ни чужих планов и разведок — иначе чужое
подтверждение блока проверок стало бы вашим. Честная оговорка: обновление закрывает **канал
доставки**, а уже приехавший ранее `VERIFY.lock` не удаляет — как это лечится, написано ниже,
в «Подтверждении блока (`--accept`)».

**Перенос старой истории.** Проект жил на версии до 1.10 — `/cckit_update` предложит перенос
сам. Вручную: `node .claude/hooks/migrate-tasks.mjs --plan` показывает предпросмотр, потом
`--apply` переносит. Хук **копирует и никогда не удаляет**, но отката у операции нет, поэтому
`--apply` намеренно не выдан в `allow`.

**Права.** В `allow` — одиннадцать точных строк: `task.mjs list`, `path`, `close` и восемь
статусов поимённо. В `deny` — четыре: `Write`/`Edit` по `.claude/tasks/**/STATE.md`
и по `.claude/tasks/ACTIVE`; они уже есть в образце `permissions.deny` ниже по файлу.
Две вещи про них надо сказать честно:

- `deny` закрывает `Write` и `Edit`, но **не `Bash`**. Это рубеж видимости, а не стена:
  статус меняют командой `task.mjs status`, и правка файла руками становится заметным
  действием, а не обычной работой;
- отсутствие команды в `allow` **не гарантирует**, что спросят вас (проверено 25.08.2026).
  Поэтому защита от свободного текста в командной строке построена на очистке входа внутри
  самого хука, а не на составе `allow`.

Правила `allow`/`deny` для задач `/cckit_update` в ваш `settings.json` не привозит — как
и правила для журнала событий, их вставляет человек руками, а Claude Code после этого
перезапускается полностью.

## Машинная приёмка (гейт проверок)

Обычно «готово» — это слово агента. Машинная приёмка делает его состоянием: помощник
`implementer` перед работой взводит гейт (`gate.mjs --arm`, без аргумента), а на завершении хода
Stop-хук `gate.mjs` прогоняет проверки проекта через `verify.mjs`. Красный результат
**возвращает ход агенту** с текстом упавшей проверки и требует зелёного прогона.

Честно о границах: это рубеж видимости, а не непроходимая стена. Обойти гейт возможно — но
любой обход остаётся **осознанным действием, видимым в логе**: агенту закрыты правки файлов
приёмки и настроек, а команды снятия гейта не выданы ему в `allow`, поэтому Claude Code,
скорее всего, спросит вас. **Гарантией это не является** (проверено 25.08.2026: команда,
которой в `allow` нет, была выполнена без вопроса — её одобрил классификатор режима сессии,
набору он не принадлежит). Настоящая опора — `[СТОП]` в работе и запрет запускать набор
с отключёнными подтверждениями.

### Где живут проверки

Блок `CCKIT:VERIFY` в §2 `PROJECT_PROFILE.md` — плоский список команд:

```yaml
timeout: 300
checks:
  - name: lint
    cmd: npm run lint
  - name: test
    cmd: npm test
    timeout: 600
```

- создать пустой блок в готовом профиле — `node .claude/hooks/verify.mjs --init`;
- посмотреть команды и хеш, ничего не подтверждая, — `node .claude/hooks/verify.mjs --show`;
- посмотреть, что будет запущено, — `node .claude/hooks/verify.mjs --dry`;
- что настроено и доступно на этой машине — `node .claude/hooks/verify.mjs --selftest`;
- прогнать — `node .claude/hooks/verify.mjs` (результат ложится в `.claude/artifacts/VERIFY.json`);
- сумма `timeout` должна укладываться в 870 секунд: столько гейт отводит на весь прогон.

**Коды возврата `verify.mjs`:** `0` — прошло всё, `1` — упала проверка, `3` — проверять нечего
либо блок не подтверждён или повреждён, `4` — прошло **не всё** (часть проверок пропущена,
например нет нужного бинарника). Четвёрка отдельно от нуля намеренно: «выполнилось не всё» —
это не зелёный результат, и вызывающая сторона обязана видеть разницу.

**Секреты в `cmd` не вписывайте.** Строка команды печатается перед каждым прогоном и попадает
в `VERIFY.json`; типовые формы маскируются, но это не гарантия. Нужен токен — берите его из
окружения.

### Подтверждение блока (`--accept`)

Команды из блока исполняются **как есть, с правами вашего пользователя**, а профиль — обычный
markdown, который приезжает вместе с чужим репозиторием. Поэтому первый прогон ничего не
выполняет: `verify.mjs` печатает список команд, говорит «блок проверок не подтверждён» и выходит
с кодом 3. Подтверждает человек:

```
node .claude/hooks/verify.mjs --accept
```

- подтверждается **набор команд**, а не текст файла: правка отступа или комментария
  подтверждение не сбрасывает, правка `cmd` или `name` — сбрасывает, и вопрос задаётся заново;
- подтверждение лежит в `.claude/artifacts/VERIFY.lock` и выдаётся **под набор команд**:
  ни к машине, ни к проекту оно не привязано. Не путешествует оно по другой причине —
  `artifacts/` стоит в `.gitignore`, а с 1.14.0 `/cckit_update` ещё и не доносит этот файл
  из мастер-копии. Файл, попавший к вам иным путём (скопировали папку целиком, положили
  руками), сделает блок «подтверждённым» без вашего «да» — тогда удалите
  `.claude/artifacts/VERIFY.lock` и выдайте подтверждение сами;
- **блок из чужого репозитория читайте глазами.** Подтверждение защищает от «выполнилось молча
  при открытии проекта», а не от плохой команды.

### Если менять проверки посреди задачи

При взведённом гейте изменение набора проверок **останавливает приёмку**: гейт запомнил один
набор команд, а в профиле стал другой. Это не поломка, а защита — иначе красный прогон можно было
бы «починить», переписав сами проверки. Что делать: вернуть блок в прежний вид или подтвердить
новый (`--accept`) и взвести гейт заново.

### Взвод и снятие

Взводит гейт `implementer` — командой `gate.mjs --arm` **без аргумента**: название берётся из
активной задачи. Форма `--arm "<текст>"` оставлена человеку и `gate.bat`. **Снять взвод может только
человек:** `node .claude/hooks/gate.mjs --disarm`. Зелёный прогон снимает гейт сам; брошенную
задачу закрывают счётчик попыток (три неудачи → приёмка останавливается) и TTL 6 часов.
Статус самой задачи гейт при этом не трогает.

Симметрично: `--arm` вы можете выполнить и руками — если вели задачу сами, а машинную приёмку
на неё всё-таки хотите. Посмотреть текущее состояние — `node .claude/hooks/gate.mjs --status`,
посчитать решение без последствий — `--dry`.

### Строка «ход завершается без приёмки»

Появляется, когда проверки настроены и подтверждены, в дереве есть правки, а гейт **не взведён**
(забыли `--arm`, оборвалась сессия) или взвод протух по TTL. Она **не блокирует** — только делает
видимым, что ход закончился без машинной приёмки: иначе это неотличимо от «в проекте нет
проверок». Нужна приёмка — взведите гейт и повторите прогон. На чистом дереве и в проектах без
проверок гейт по-прежнему молчит.

### Если гейт мешает

Четыре рычага, по возрастанию грубости — все четыре действия человека:

1. `node .claude/hooks/gate.mjs --disarm` — снять взвод на текущей задаче;
2. пустой `checks: []` в блоке `CCKIT:VERIFY` — проверок нет, гейт молчит везде;
3. переменная окружения `CCKIT_GATE` со значением `off`, `0` или `false` — отключить на сессию
   (значение вроде `maybe` гейт не отключает; из уже запущенной сессии Claude Code переменная
   не меняется — задавайте её до запуска);
4. аварийно — `.claude/settings.local.json` с `{"disableAllHooks": true}` и **полный перезапуск**
   Claude Code. Точечно убрать один хук этим файлом нельзя: настройки объединяются, а не
   замещаются, поэтому выключается сразу всё.

### Что гейт и `deny` не ловят

- Правила `deny` на git сопоставляются с текстом команды и ловят **только прямую форму**
  (`git push`, `git reset --hard`, `git clean`). Эквиваленты — `git -C . push`,
  `sh -c "git push"`, `env git push`, `npm run deploy` — этими правилами не ловятся.
  Это **лежачий полицейский, а не граница.**

  В отдельных режимах Claude Code часть таких обходов перехватывает собственный классификатор
  среды, но **он не принадлежит набору**: в другом режиме сессии его может не быть, и полагаться
  на него нельзя. Настоящая граница — две вещи: контрольные точки `[СТОП]`, на которых решение
  принимает человек, и то, что **набор не запускают в режиме с отключёнными подтверждениями**.

  ⚠️ **Не запускайте кит с отключёнными подтверждениями** (режимы, где действия выполняются
  без вопросов). В таком режиме и `deny`, и `[СТОП]` перестают быть опорой: остаётся только
  добрая воля агента, а именно её эта фаза и должна была заменить.
- Строка `cmd:` внутри самого блока `CCKIT:VERIFY` исполняется хуком мимо слоя прав — поэтому
  блок и защищён подтверждением, а не разрешениями.
- **Подмена самого измерителя.** Гейт запоминает при взводе хеш `verify.mjs`, `gate.mjs`
  и набора проверок, и печатает отметку, если они изменились. Это **видимость, а не защита**:
  ход не блокируется (правка хуков — законное занятие), а за пределы конвейера хеш не достаёт.
  Команды блока вызывают чужой код — подмените тесты, и приёмка позеленеет, не тронув ни одного
  из хешируемых кусков.
- **Как вернуть себе push:** уберите соответствующие строки из `permissions.deny` в
  `.claude/settings.json`. Файл принадлежит вашему проекту, менять его — ваше право.

### Слепая зона свежести

`node .claude/hooks/verify.mjs --fresh` отвечает, относится ли последняя приёмка к нынешнему
состоянию дерева. Отпечаток считается по git, поэтому **правки в игнорируемых путях свежесть
не сбрасывают** — а в проекте с развёрнутым набором игнорируется весь `.claude/**`. Правили
промты или профиль — на `--fresh` не опирайтесь.

### Секреты в артефактах

В `VERIFY.json` попадают строки команд и хвост вывода упавшей проверки (до 40 строк и 4 КБ).
Файлы `VERIFY.json`, `VERIFY.lock` и `GATE_STATE.json` пишутся с правами `0600`, перечислены
в `.gitignore` отдельными строками и не уезжают через `/cckit_push-with-me`. Типовые формы
секретов маскируются (`***`), но **полагаться на маску нельзя**.

## Журнал событий

`.claude/artifacts/events.jsonl` — машинный журнал проекта: одна строка JSON на событие.
Файл только **дописывается** и никогда не перезаписывается, поэтому по нему потом строятся
статистика, ретроспектива и дашборд.

Пишут в него два хука, специально ничего делать не нужно:

- `task.mjs` — `task_opened` (задача заведена), `status_changed` (сменился статус; на переходе
  в `reworking` payload несёт ещё и `iteration` — номер итерации ревью),
  `task_closed` (задача закрыта, с полем `duration_min`);
- `gate.mjs` — `gate_result` (вердикт машинной приёмки: `pass`, `partial`, `fail`, `blocked`,
  `none`, `stale`).

Строка выглядит так — четыре ключа всегда и в этом порядке:

```
{"ts":"2026-08-27T11:22:33.123Z","task_id":"2026-08-27-imya","event":"status_changed","payload":{"from":"planning","to":"implementing"}}
```

`ts` — UTC в формате ISO-8601 с миллисекундами: без смещения строки нельзя сравнить между
машинами, а без секунд два события одной минуты неразличимы по порядку. Человекочитаемое время
осталось в `STATE.md` задачи и никуда не делось.

Посмотреть последние записи: `node .claude/hooks/events.mjs --selftest`. Файл лежит под
`.gitignore` вместе со всем `artifacts/` — названия задач и имена упавших проверок в репозиторий
не уезжают. **Ротации нет**: журнал растёт линейно, порядка сотни байт на событие; надоел —
удалите файл, дописывание начнётся заново.

**Три обязанности у того, кто журнал читает.** Первая: пропускать нечитаемую строку, а не
падать на ней — лока у файла нет, и две параллельные сессии теоретически способны наложить
запись. Вторая: экранировать значения при выводе в HTML. Очистка убирает управляющие символы,
но `<`, `>` и `&` не трогает, и название задачи вида `фикс <script> в шапке` доедет до журнала
как есть; готовый образец экранирования в наборе уже есть — `esc()` в `.claude/hooks/map.mjs`.

Третья: не считать сбоем запись `status_changed`, у которой `from` совпал с `to`. Такое
случается, когда статус выставили повторно, и журнал обязан это показать как есть: строку
в `STATE.md` пишет `task.mjs status` безусловно, и отфильтруй мы событие — журнал разошёлся
бы со `STATE.md`. Две правды об одной задаче хуже, чем одна скучная запись.

**И главное: журнал — рубеж видимости, а не доказательство.** Два правила
`Write(.claude/artifacts/events.jsonl)` и `Edit(.claude/artifacts/events.jsonl)` в образце
`permissions.deny` выше закрывают прямую правку файла, но не `Bash`, а сама команда
`node .claude/hooks/events.mjs --emit …` — санкционированный способ дописать строку, байт в байт
неотличимую от настоящей. Журнал делает работу видимой; уликой он не становится. Поэтому его
записи **сверяют** со `STATE.md` задачи и `artifacts/VERIFY.json`, а не заменяют их ими.

## Обновление настроек в открытом Claude Code

Файл `settings.json` читается при запуске. После правки полностью перезапустите Claude Code
(команда очистки истории настройки не перечитывает).
