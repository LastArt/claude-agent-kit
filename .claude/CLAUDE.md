# CLAUDE.md — разработка самого Claude Agent Kit

> Этот файл — про работу **над набором**, а не про проект пользователя. Он намеренно лежит
> внутри `.claude/`, чтобы не мешаться в корне рядом с пользовательским `CLAUDE.md`,
> и **не распространяется**: установщики удаляют его из копии, уходящей в `~/.claude/agent-kit/`,
> а команды разворачивания его не копируют.
>
> Полная специфика проекта — в [PROJECT_PROFILE.md](PROJECT_PROFILE.md). Здесь только то,
> что нужно помнить с первой секунды.

## Главное, что ломает людей в этом проекте

**Папка `.claude/` — это одновременно конфигурация текущего проекта и payload, который
копируется пользователям.** Правка любого файла здесь расходится по всем будущим проектам.
Прежде чем что-то менять, спроси себя: «это правило для ЭТОГО репозитория или для всех, кто
поставит набор?» Первое — в `settings.local.json` или в профиль, второе — сюда.

Исключения, которые НЕ распространяются (следи, чтобы так и оставалось): этот файл и
`settings.local.json`.

**Отдельно про профиль.** `PROJECT_PROFILE.md` здесь описывает сам набор — раздавать его
пользователям нельзя, иначе их проекты стартуют с чужими фактами. В мастер-копию и в проекты
уезжает `PROJECT_PROFILE.template.md`; подмену делают установщики и команды разворачивания.
Меняешь структуру профиля — **правь оба файла**, иначе шаблон и реальность разойдутся.

## Жёсткие правила

- **Никаких внешних зависимостей.** Ни в хуках, ни где-либо ещё: набор обязан работать сразу
  после распаковки ZIP, без `npm install`. Нужен парсер — бери встроенный в Node.
- **`install.ps1` — только ASCII.** Windows PowerShell 5.1 читает `.ps1` в системной кодировке,
  кириллица ломает разбор файла целиком.
- **Окончания строк:** `.sh` и `.mjs` — только LF, `.ps1` — CRLF (см. `.gitattributes`).
- **Имя файла агента = поле `name` во front-matter.** Расходятся — агент не вызывается.
  Хук `check-syntax.mjs` это проверяет и блокирует.
- **Версия живёт в одном месте** — `.claude/VERSION`. Меняешь её — обнови и `CHANGELOG.md`.
- **Окно чата не показывает локальные картинки.** Проверено: `![](assets/logo.png)` в ответе
  помощника выводится сырой строкой. Поэтому логотип в приветствии — текстовый
  (`.claude/assets/logo.txt`), а PNG используется только там, где картинки работают: README
  на GitHub и предпросмотр markdown в VS Code. Не «чини» это обратно на картинку.
- **Логотип меняется файлом, а не кодом.** Полный знак — `.claude/assets/logo.txt`, узкий —
  `logo-mini.txt`. `banner.mjs` только выбирает подходящий по ширине окна. Не переноси
  рисунок обратно в код.
- **Набор не коммитится в проект пользователя.** Развёрнутый кит живёт внутри чужого
  репозитория и не должен туда попадать: команды разворачивания пишут `.claude/` в его
  `.gitignore`, `commit-organizer` такие пути не стейджит. Осознанный выход — только
  `/cckit_push-with-me`. **В этом репозитории правило обратное** — здесь `.claude/` продукт
  и коммитится. Правя эти места, держи оба случая в голове.
- **Право менять прод-код есть только у `implementer`.** Не расширяй `tools:` другим агентам.
- **Рабочих файлов конвейера в репозитории нет.** `artifacts/` и `explores/` выведены из-под git
  целиком: в них лежит задача, над которой идёт работа прямо сейчас, и через `git add -A` или
  через установщик она уезжала бы в чужие проекты. В репозитории живут только эталоны —
  `assets/stubs/`. После свежего клона разложи их: `node .claude/hooks/stubs.mjs`. Правишь
  формат плана, ревью или аудита — правь **заглушку в `assets/stubs`**, иначе правка не доедет
  ни до кого.
- **Что уезжает пользователям, решает `ship.list`.** Белый список: чего в нём нет, того нет
  и в мастер-копии. Добавил новый каталог в `.claude/` — впиши его туда, иначе он просто
  не доедет (и это заметно на первом же запуске — так и задумано).
- **Stop-гейт действует и в этом репозитории.** `gate.mjs` зарегистрирован в
  `.claude/settings.json` (позиция `Stop`, таймаут 900), и самоотключения по признаку «мы внутри
  набора» нет и не будет: признак пришлось бы нести в payload, а взвод через
  `gate.mjs --arm "<задача>"` эту задачу и так решает. Новую версию любого из двух хуков сначала
  гоняем `--dry` и `--selftest`, и только потом даём ей встать в `Stop`. Рычаги разблокировки —
  четыре, все перечислены в [CUSTOMIZE.md](CUSTOMIZE.md), раздел «Машинная приёмка».
- **Якоря доверия закрыты намеренно.** `.claude/artifacts/VERIFY.json`, `VERIFY.lock`,
  `GATE_STATE.json`, `settings.local.json` и сам `settings.json` закрыты в `permissions.deny`
  от правки агентом, а изменение блока `CCKIT:VERIFY` в `PROJECT_PROFILE.md` при взведённом
  гейте уводит задачу в `blocked`. Это результат аудита фазы 1, а не недосмотр: **не «чини» это
  расширением прав**.
- **`deny` на git — лежачий полицейский, а не граница.** Правила ловят прямую форму команды;
  `git -C . push`, `sh -c "git push"` и `npm run deploy` — нет. Часть обходов перехватывает
  классификатор среды, но он не наш и в другом режиме сессии не сработает. Граница — `[СТОП]`
  и запрет запускать набор с отключёнными подтверждениями. Не пиши в документации, будто
  правами что-то «отклоняется» — это неправда, и на неё начнут рассчитывать.
- **Если гейт сломан здесь же — чинит человек, руками.** `settings.json` агенту закрыт правами,
  и правится он в редакторе, вне Claude Code. Агент обязан остановиться и сказать об этом прямо,
  а не искать обход через `Bash`, `cat >`, `settings.local.json` или переменные окружения.
  Порядок для человека: `CCKIT_GATE=off` на сессию → правка `settings.json` руками → полный
  перезапуск Claude Code.

## Как проверять свою работу

Автотестов нет. Обязательный минимум после правок:

```bash
node --check .claude/hooks/check-syntax.mjs      # и любой другой изменённый .mjs
node .claude/hooks/check-syntax.mjs --selftest   # что реально проверяется
node .claude/hooks/banner.mjs                    # баннер не разъехался
bash -n install.sh                               # синтаксис установщика
node .claude/hooks/verify.mjs --selftest         # что настроено в приёмке и подтверждено ли
node .claude/hooks/gate.mjs --dry                # решение гейта без последствий
```

Про машинную приёмку в этом репозитории:

- на новой машине блок проверок подтверждается **один раз**: `node .claude/hooks/verify.mjs
  --accept` — **из терминала**: команда печатает набор, спрашивает «да» с клавиатуры и без TTY
  не работает вовсе. Посмотреть, что предлагается, можно без подтверждения: `--show`;
- сам список проверок лежит в `PROJECT_PROFILE.md` §2, блок `CCKIT:VERIFY`;
- `--fresh` здесь малополезен: у пользователей весь `.claude/**` игнорируется git, а тут
  наоборот отслеживается. Не переноси вывод из одного случая в другой.

Полный ручной сценарий (включая проверку блокировки на битом файле и разворачивание в тестовую
папку) — в `PROJECT_PROFILE.md` §7. Правки в `.claude/**` проверяются **на развёрнутой копии**,
а не в этой папке: здесь набор сам себя не обслуживает.

## Куда что добавлять

| Что | Куда |
|-----|------|
| Новый агент | `.claude/agents/<имя>.md` + строка в таблице `ORCHESTRATOR_PROMPT.md` + команда `/cckit_<...>` |
| Новая команда | `.claude/commands/cckit_<действие>.md`; глобальная — ещё и в `GLOBAL_COMMANDS` **обоих** установщиков |
| Факт о проекте | `PROJECT_PROFILE.md` — никогда не в промт агента |
| Правило для всех проектов | промт агента или `settings.json` (помни: это payload) |
