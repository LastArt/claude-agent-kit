# PROJECT PROFILE — Claude Agent Kit

> Единственный файл со спецификой проекта. Все агенты читают его вместо «зашитых» фактов.
> Заполняется командой `/cckit_research` (разведка репозитория). Незакрытые `TODO` — впиши руками.
> Меняются команды/пути/стиль — правь ТОЛЬКО этот файл, агентов не трогай.

**Статус профиля:** 🟢 заполнен по разведке репозитория
**Дата заполнения:** 2026-08-10
**Версия набора:** см. `.claude/VERSION` (единственное место хранения; вывести —
`node .claude/hooks/banner.mjs`)

> ⚠️ **Особенность этого проекта:** он сам является Claude Agent Kit — набором настроек для
> Claude Code. Папка `.claude/` здесь имеет **двойную роль**: это и конфигурация текущего
> проекта, и **payload, который копируется в проекты пользователей** (`install.ps1` / `install.sh`
> → `~/.claude/agent-kit/` → `/cckit_new-project`). Любая правка в `.claude/**` расходится
> по всем будущим проектам. Учитывай это в каждой задаче.

## 1. Что за проект

- **Название:** Claude Agent Kit (префикс команд — `cckit`)
- **Одно предложение:** набор готовых настроек для Claude Code — мультиагентный конвейер из
  девяти субагентов, оркестраторный промт, хуки, шаблоны артефактов и команды разворачивания;
  устанавливается один раз в `~/.claude/` и разворачивается в любой проект пользователя.
- **Язык(и):**
  - Markdown — основное «тело» продукта (промты агентов и команд, документация);
  - JavaScript (ESM, Node) — хуки;
  - PowerShell 5.1 + Bash — установщики.
- **Backend:** нет
- **Frontend:** нет
- **База данных / ORM:** нет
- **Менеджер(ы) пакетов:** нет. `package.json` отсутствует, внешних зависимостей нет —
  и это осознанное требование: набор должен работать сразу после распаковки, без `npm install`.
  Node нужен только как рантайм для хуков (18 и новее).

- **`install.ps1` обязан оставаться ASCII-only** — Windows PowerShell 5.1 читает `.ps1` в

- **Окончания строк критичны** (`.gitattributes`): `*.sh` и `*.mjs` — только LF (иначе bash/node

  `node .claude/hooks/check-syntax.mjs --selftest`. JS, JSON, YAML и front-matter проверяются

  заглушка Microsoft Store вместо Python (хук распознаёт её пробным запуском и не притворяется,
  что проверил), а TS/JSX без `@babel/parser` в проекте проверяются только на обрыв файла.
- **Команды `/cckit_new-project` и `/cckit_install` намеренно отказываются разворачиваться
  в эту папку** (защита по маркерам: в корне есть одновременно `install.ps1` и `install.sh`).
  Это ожидаемое поведение, не баг.

## 3. Структура кода

- **Backend модули / где логика:** backend нет. «Логика» продукта — это текст промтов:
  - `.claude/agents/` — 9 субагентов (`explorer`, `planner`, `security-auditor`, `implementer`,
    `reviewer`, `documenter`, `faq-writer`, `changelog-writer`, `commit-organizer`);
  - `.claude/ORCHESTRATOR_PROMPT.md` — промт оркестратора, режимы цепочек A–F/R;
  - `.claude/commands/` — **единственный источник всех команд**. Шесть из них
    (`cckit_new-project`, `cckit_install`, `cckit_update`, `cckit_uninstall`, `cckit_help`,
    `cckit_get_instruction`) установщик копирует в `~/.claude/commands/`, чтобы они работали
    в любой папке; остальные остаются проектными. Список глобальных задаётся в обоих
    установщиках переменной `GLOBAL_COMMANDS` — добавляешь глобальную команду, правь оба;
  - `.claude/hooks/check-syntax.mjs` — PostToolUse-хук (после `Edit`/`Write`/`NotebookEdit`);
  - `.claude/hooks/git-status.mjs` — Stop-хук (краткая сводка правок; на чистом дереве молчит);
  - `.claude/hooks/archive-task.mjs` — убирает завершённые `PLAN.md`/`SECURITY.md`/`REVIEW.md` в
    `artifacts/history/`. Вызывается **оркестратором** перед `planner` (у `planner` нет Bash);
  - `.claude/hooks/stats.mjs` — статистика по токенам, моделям и инструментам. Читает
    транскрипты Claude Code из `~/.claude/projects/<кодированный-путь>/*.jsonl` — **формат
    недокументирован**, поэтому скрипт обязан не падать, а честно сообщать, что данных нет;
  - `.claude/hooks/banner.mjs` — три вида приветствия: ASCII для терминала (установщики),
    компактная строка для SessionStart-хука и `--welcome` — markdown с настоящей картинкой,
    который помощник вставляет в свой ответ;
  - `.claude/WELCOME.md` — текст окна приветствия с подстановками `{{LOGO}}`, `{{VERSION}}`,
    `{{AGENTS}}`, `{{COMMANDS}}`, `{{PROFILE}}`, `{{NEXT}}`; витрина, а не логика —
    правится свободно;
  - `.claude/assets/logo.txt` и `logo-mini.txt` — логотип текстом, полный и узкий;
    подменяются без правки кода. В приветствии всегда полный знак (блок кода прокручивается),
    в терминале — по ширине окна: полный → `logo-mini.txt` → первый блок полного →
    одна строка с названием;
  - `.claude/VERSION` — версия набора, **единственное место хранения**;
  - `.claude/settings.json` — права и регистрация хуков;
  - `.claude/artifacts/` — шаблоны `PLAN.md`, `REVIEW.md`, `FAQ_TEMPLATE.md`;
  - `.claude/artifacts/history/` — память проекта: планы и ревью завершённых задач плюс
    `INDEX.md`. Хранит то, чего нет в коде, — почему сделали так и что отвергли. Читается
    `explorer` перед разведкой и командой `/cckit_recall`;
  - `.claude/CLAUDE.md` — инструкции по разработке самого набора; **не распространяется**
    (установщики удаляют, команды разворачивания не копируют);
  - `.claude/PROJECT_PROFILE.template.md` — чистый шаблон профиля. **Этот** файл уезжает
    в проекты под именем `PROJECT_PROFILE.md`, а заполненный профиль репозитория остаётся
    здесь. Меняешь структуру профиля — правь оба файла.
- **Команды по одной на агента:** `cckit_explore`, `cckit_plan`, `cckit_audit`, `cckit_implement`,
  `cckit_review`, `cckit_docs`, `cckit_faq`, `cckit_release`, `cckit_commits` — каждая
  запускает ровно одного агента и останавливается. Добавляешь агента — добавь и команду,

- **Точки входа:** `install.ps1` / `install.sh` — установка набора в `~/.claude/`.
- **Миграции БД:** нет (БД нет).

## 4. Конвенции (чтобы агенты не ломали стиль)

- **Именование:**
  - Агенты — `.claude/agents/<kebab-case>.md`; имя файла **обязано совпадать** с полем `name`
    во front-matter.
  - Команды — `.claude/commands/cckit_<действие>.md`; аргумент подставляется через `$ARGUMENTS`.
  - Корневые доки — ВЕРХНИМ регистром (`README.md`, `SETUP.md`, `CUSTOMIZE.md`,
    `PROJECT_PROFILE.md`, `ORCHESTRATOR_PROMPT.md`).
- **Стиль Node-скриптов (`.mjs`):** shebang `#!/usr/bin/env node`; ESM (`import`, не `require`);
  в шапке — блочный JSDoc-комментарий на русском, объясняющий назначение и поведение;
  **только встроенные модули `node:*`, никаких внешних зависимостей**; кроссплатформенность
  обязательна (пути через `node:path`, без shell-специфичных операторов); отсутствие внешнего
  инструмента — не ошибка, а мягкий выход. Комментарии объясняют **почему** так сделано,
  а не пересказывают код.
- **Стиль промтов (агенты/команды):** обращение на «ты» («Ты — исполнитель, …»); разделы `##`;
  явный блок жёстких правил; **специфика проекта не хардкодится** — агент читает её из этого
  файла. Front-matter агента: `name`, `description`, `tools` (через запятую), `model: inherit`.
  Front-matter команды: только `description`.
- **Язык:** вся пользовательская документация и промты — на русском. Исключение —
  `install.ps1` (ASCII-only английский, техническое ограничение).
- **Жёсткие запреты:**
  - **Не добавлять внешних зависимостей** — ни в хуки, ни куда-либо ещё. Набор обязан работать
    сразу после распаковки ZIP.
  - **Не хардкодить домашний путь пользователя** — определять `%USERPROFILE%` / `$HOME`
    в рантайме.
  - **Не хардкодить специфику конкретного проекта в агентов** — только через `PROJECT_PROFILE.md`.
  - **Не вписывать не-ASCII в `install.ps1`.**
  - **Разворачивание всегда additive:** существующие файлы проекта не перезаписывать, всё
    пропущенное громко перечислять в конце.
  - **Не расширять `tools:` агентам без явной нужды** — право менять код есть только у
    `implementer` (см. §5).
  - **Не распространять `settings.local.json`** — ни в `~/.claude/agent-kit/`, ни в проекты.
  - Помнить, что `.claude/**` — распространяемый payload (см. врезку в шапке).
- **Эталонный модуль-образец:**
  - агент — `.claude/agents/implementer.md`;
  - команда — `.claude/commands/cckit_new-project.md`;
  - Node-скрипт — `.claude/hooks/check-syntax.mjs`.

## 5. Права доступа / авторизация

- **Модель:** не RBAC и не ownership. Права здесь — **инструментальные**, в двух слоях:
  1. поле `tools:` во front-matter каждого агента (что агенту вообще доступно);
  2. `permissions.allow` / `permissions.deny` в `.claude/settings.json`.
- **Где проверяется:** обеспечивается самим Claude Code при вызове агента/инструмента.
  `deny` переопределяет `allow` и действует в любом режиме, включая `acceptEdits`.
- **Ловушки:**
  - Право менять прод-код есть **только у `implementer`** (`Read, Write, Edit, Bash`).
    Остальные — read-only или Write только в свои артефакты. Расширение `tools:` у любого
    другого агента ломает главную гарантию конвейера — не делать без решения человека.
  - `defaultMode: acceptEdits` снимает подтверждение правок, но **не снимает** `deny`.
  - `settings.json` читается **при старте** Claude Code: после правки нужен полный перезапуск,
    `/clear` настройки не перечитывает. То же касается новых команд и агентов.
  - `.claude/settings.local.json` создаётся Claude Code автоматически (локальные разрешения
    машины). Он в `.gitignore`, и оба установщика удаляют его из распространяемой копии.
- **Что НЕЛЬЗЯ гейтить общей матрицей ролей:** н/д.
- **Граница «набор ↔ проект пользователя».** Развёрнутый набор живёт внутри чужого
  репозитория, поэтому его файлы не должны туда попадать: команды разворачивания добавляют
  `.claude/` в `.gitignore` проекта, `commit-organizer` обязан их не стейджить, а вынести
  вопросом. Единственный осознанный выход наружу — команда `/cckit_push-with-me`, и даже она
  никогда не включает `settings.local.json`.

## 7. Проверка и деплой (как реально убедиться, что не сломано)

- **Автотесты:** нет.
- **Ручной сценарий проверки** (заменяет автотесты):
  1. `node --check .claude/hooks/check-syntax.mjs` и `node --check .claude/hooks/git-status.mjs`
     — оба скрипта разбираются без ошибок;
  2. `node .claude/hooks/check-syntax.mjs --selftest` — показывает, что доступно на машине;
  3. проверка на битом файле: создать временный файл с заведомо сломанным синтаксисом и скормить
     хуку — `echo '{"tool_input":{"file_path":"<АБСОЛЮТНЫЙ путь>"}}' | node .claude/hooks/check-syntax.mjs`;
     ожидание — текст ошибки и код возврата **2**. Путь обязательно нативный для ОС
     (на Windows `C:/…`, а не `/c/…`), иначе хук просто не найдёт файл и промолчит;
  4. прогнать `install.ps1` / `install.sh` → проверить, что появились `~/.claude/agent-kit/`
     (без `settings.local.json`) и `~/.claude/commands/cckit_{new-project,install,help}.md`;
  5. **полностью перезапустить Claude Code** → в произвольной папке проверить, что видны три
     глобальные команды;
  6. развернуть набор в тестовую папку (`/cckit_new-project probe`) → убедиться, что видны
     команды и девять агентов.
- **Как проверяется корректность:** только ручным сценарием выше. Правки в `.claude/**`
  проверяются не «в этой папке», а на **развёрнутой копии** в тестовом проекте — здесь набор
  сам себя не обслуживает.
- **Порядок деплоя:**
  1. изменить файлы в `claude-agent-kit/`;
  2. заново запустить `install.ps1` / `install.sh` (обновляет `~/.claude/agent-kit/`);
  3. полностью перезапустить Claude Code;
  4. в **уже развёрнутых** проектах файлы не обновляются автоматически — недостающее
     добавляется командой `/cckit_install` (существующее не затирается).
  Распространение — копированием папки (git / архив / носитель). Пуш и публикация — на человеке.

## 8. Git / VCS

- **Remote:** публичный репозиторий на GitHub (`LastArt/claude-agent-kit`, лицензия MIT).
- **Основная ветка:** `main`.
- **Политика push:** push и деплой — **на человеке**, агенты не пушат
  (правило из `ORCHESTRATOR_PROMPT.md`). `commit-organizer` коммитит только локально.
- **Стиль коммитов:** Conventional Commits (`<тип>(<область>): <суть>`), сообщения на русском,
  одна логическая правка на коммит. Типы: `feat`, `fix`, `docs`, `refactor`, `chore`.
- **Что не коммитим:** `.claude/settings.local.json` (локальные разрешения машины) — он
  в `.gitignore`. Перед коммитом убедись, что в правках нет абсолютных путей с именем
  пользователя и машинно-специфичных фактов: этот репозиторий публичный.
- **Внимание — асимметрия:** здесь `.claude/` коммитится, потому что это продукт. В проектах
  пользователей действует обратное правило: набор туда не коммитится вообще (см. §5).
  Правя команды разворачивания и `commit-organizer`, не перепутай эти два случая.

## 9. Секреты под защитой (для settings.json → permissions.deny)

> Файлы, которые агентам нельзя читать/писать. `/cckit_research` переносит этот список в
> `settings.json`. По умолчанию: `.env`, `*.pem`, `*.key`, приватные ключи.

- **Реальных файлов секретов в проекте нет** — ни `.env`, ни ключей, ни токенов.
  Действующие правила `deny` в `.claude/settings.json` закрывают на чтение и запись:
  `.env`, `**/.env`, `**/.env.*`, `**/*.pem`, `**/*.key`.
- `.claude/settings.json` — **распространяемый payload**. Любое правило, добавленное «под этот
  репозиторий», протечёт во все проекты, создаваемые набором. Поэтому здесь только универсальные
  запреты; локальные разрешения держи в `.claude/settings.local.json`.
- `.claude/settings.local.json` — не секрет, но и не для распространения: он в `.gitignore`,
  и оба установщика удаляют его из копии, уходящей в `~/.claude/agent-kit/`. Команды
  разворачивания тоже проинструктированы его не копировать.
