# PROJECT PROFILE — Claude Agent Kit

> Единственный файл со спецификой проекта. Все агенты читают его вместо «зашитых» фактов.
> Заполняется командой `/cckit_research` (разведка репозитория). Незакрытые `TODO` — впиши руками.
> Меняются команды/пути/стиль — правь ТОЛЬКО этот файл, агентов не трогай.

**Статус профиля:** 🟢 заполнен по разведке репозитория
**Дата заполнения:** 2026-08-10
**Версия набора:** см. `.claude/VERSION` (единственное место хранения; вывести —
`node .claude/hooks/banner.mjs`)

> ⚠️ **Особенность этого проекта:** он сам является Claude Agent Kit — набором настроек для
> Claude Code. Папка `.claude/` здесь имеет **двойную роль**: это и конфигурация текущего
> проекта, и **payload, который копируется в проекты пользователей** (`install.ps1` / `install.sh`
> → `~/.claude/agent-kit/` → `/cckit_new-project`). Любая правка в `.claude/**` расходится
> по всем будущим проектам. Учитывай это в каждой задаче.

## 1. Что за проект

- **Название:** Claude Agent Kit (префикс команд — `cckit`)
- **Одно предложение:** набор готовых настроек для Claude Code — мультиагентный конвейер из
  девяти субагентов, оркестраторный промт, хуки, шаблоны артефактов и команды разворачивания;
  устанавливается один раз в `~/.claude/` и разворачивается в любой проект пользователя.
- **Язык(и):**
  - Markdown — основное «тело» продукта (промты агентов и команд, документация);
  - JavaScript (ESM, Node) — хуки;
  - PowerShell 5.1 + Bash — установщики.
- **Backend:** нет
- **Frontend:** нет
- **База данных / ORM:** нет
- **Менеджер(ы) пакетов:** нет. `package.json` отсутствует, внешних зависимостей нет —
  и это осознанное требование: набор должен работать сразу после распаковки, без `npm install`.
  Node нужен только как рантайм для хуков (18 и новее).

> Точные команды из конфигов (package.json scripts, Makefile, pyproject, CI). Если чего-то

```yaml

checks:
  - name: syntax-verify
    cmd: node --check .claude/hooks/verify.mjs
  - name: syntax-gate
    cmd: node --check .claude/hooks/gate.mjs
  - name: syntax-selftest
    cmd: node .claude/hooks/check-syntax.mjs --selftest
  - name: banner
    cmd: node .claude/hooks/banner.mjs --compact
  - name: install-sh
    cmd: bash -n install.sh
```
<!-- /CCKIT:VERIFY -->

Блок выше — машинная приёмка: его читает `node .claude/hooks/verify.mjs`, а Stop-гейт
`gate.mjs` по нему решает, можно ли закончить ход. Четыре вещи, которые важно понимать:

- **Всё, что написано в этом блоке, будет выполнено как есть, с правами вашего пользователя.**
  Блок, приехавший из чужого репозитория, прочитайте глазами, прежде чем подтверждать.
- **Первый прогон требует подтверждения:** `node .claude/hooks/verify.mjs --accept`
  (при изменении команд — заново; правка отступа или комментария подтверждение не сбрасывает).
- **Секреты в `cmd` не вписывайте.** Этот файл читают агенты, а строка команды печатается в лог
  перед каждым прогоном и попадает в `VERIFY.json`. Маскирование типовых форм есть, но полагаться
  на него нельзя: нужен токен — берите его из окружения, а не из строки команды.
- **Заполняет блок** `/cckit_research` или вы руками; посмотреть, что будет запущено, —
  `node .claude/hooks/verify.mjs --dry`, создать пустой блок в готовом профиле —
  `node .claude/hooks/verify.mjs --init`.

Блок в файле должен быть **ровно один** (второй открывающий маркер или потерянный закрывающий —
это повреждённый блок, и `verify.mjs` откажется что-либо выполнять). Сумма `timeout` всех проверок
должна укладываться в 870 секунд — столько гейт отводит на весь прогон.

**На Windows без `bash` проверка `install-sh` даёт `skipped`, а весь прогон — статус `partial`,
а не `pass`. Это ожидаемо** и не считается провалом: `partial` честно говорит, что часть проверок
не выполнялась. Полный `pass` здесь получается только там, где есть bash.

**Ограничения окружения** (важно для агентов):

- **Автотестов, линтера, типопроверки и CI нет** (`.github/`, `.gitlab-ci.yml`, `Makefile`,
  `tox.ini` отсутствуют). Не заявляй «протестировано» — только «прошёл ручной сценарий» (§7).
- **Проект под git** (ветка `main`, remote — GitHub). `commit-organizer`, Stop-хук
  `gate.mjs` (сводку печатает `git-status.mjs`) и `reviewer` работают штатно.
- **`install.ps1` обязан оставаться ASCII-only** — Windows PowerShell 5.1 читает `.ps1` в
  системной кодировке, кириллица в нём ломает парсинг. В `install.sh` кириллица допустима.
- **Окончания строк критичны** (`.gitattributes`): `*.sh` и `*.mjs` — только LF (иначе bash/node
  на Linux/macOS падают на `\r`), `*.ps1` — CRLF, `*.png` — binary.
- **Что реально проверяется в конкретном окружении** — показывает
  `node .claude/hooks/check-syntax.mjs --selftest`. JS, JSON, YAML и front-matter проверяются
  всегда (встроенными средствами Node). Две частые оговорки: на Windows в `PATH` обычно висит
  заглушка Microsoft Store вместо Python (хук распознаёт её пробным запуском и не притворяется,
  что проверил), а TS/JSX без `@babel/parser` в проекте проверяются только на обрыв файла.
- **Команды `/cckit_new-project` и `/cckit_install` намеренно отказываются разворачиваться
  в эту папку** (защита по маркерам: в корне есть одновременно `install.ps1` и `install.sh`).
  Это ожидаемое поведение, не баг.

## 3. Структура кода

- **Backend модули / где логика:** backend нет. «Логика» продукта — это текст промтов:
  - `.claude/agents/` — 9 субагентов (`explorer`, `planner`, `security-auditor`, `implementer`,
    `reviewer`, `documenter`, `faq-writer`, `changelog-writer`, `commit-organizer`);
  - `.claude/ORCHESTRATOR_PROMPT.md` — промт оркестратора, режимы цепочек A–F/R;
  - `.claude/commands/` — **единственный источник всех команд**. Шесть из них
    (`cckit_new-project`, `cckit_install`, `cckit_update`, `cckit_uninstall`, `cckit_help`,
    `cckit_get_instruction`) установщик копирует в `~/.claude/commands/`, чтобы они работали
    в любой папке; остальные остаются проектными. Список глобальных задаётся в обоих
    установщиках переменной `GLOBAL_COMMANDS` — добавляешь глобальную команду, правь оба;
  - `.claude/hooks/check-syntax.mjs` — PostToolUse-хук (после `Edit`/`Write`/`NotebookEdit`);
  - `.claude/hooks/git-status.mjs` — сводка правок (на чистом дереве молчит); в позиции `Stop`
    больше не стоит сам — его вызывает подпроцессом `gate.mjs`;
  - `.claude/hooks/verify.mjs` — единая точка прогона проверок проекта. Читает машиночитаемый
    блок `CCKIT:VERIFY` из §2 этого файла, подтверждение блока держит в
    `artifacts/VERIFY.lock` (первый прогон и любая правка команд требуют
    `verify.mjs --accept` от человека), результат пишет в `artifacts/VERIFY.json`.
    Коды возврата: `0` — прошло всё, `1` — упала проверка, `3` — проверять нечего либо блок
    не подтверждён/повреждён, `4` — прошло **не всё** (`partial`: часть проверок пропущена
    или прогон частичный). Четвёрка отдельно, потому что «упало» и «выполнилось не всё» —
    разные ситуации: ноль при пропусках был бы тихим ложным зелёным. Режимы: `--dry`, `--selftest`, `--only <имя>`, `--fresh`, `--init`,
    `--show` (показать команды и хеш, ничего не записывая), `--accept` (**только из терминала**:
    спрашивает «да» с клавиатуры, при отсутствии TTY отказывает с кодом 3), служебный `--hash`;
  - `.claude/hooks/gate.mjs` — Stop-хук, машинная приёмка. Взводится командой
    `node .claude/hooks/gate.mjs --arm` — **без аргумента**: название берётся из активной
    задачи. Взводит `implementer` перед первым шагом плана. Форма `--arm "<текст>"` оставлена
    человеку и `gate.bat`. Состояние держит в `artifacts/GATE_STATE.json`. При взведённом гейте
    сверяет `checks_hash` с текущим блоком проверок и гоняет `verify.mjs`: красный результат →
    `exit 2` (ход возвращается агенту), три неудачные попытки или подмена набора проверок →
    `blocked` и `exit 0` (дальше решает человек). Невзведённый гейт на грязном дереве печатает
    заметную строку «ход завершается без приёмки», но не блокирует; сводку git печатает всё тот
    же `git-status.mjs`;
  - `.claude/hooks/events.mjs` — машинный журнал событий `artifacts/events.jsonl`: одна строка
    JSON на событие, файл только дописывается и никогда не перезаписывается. Пишут в него
    `task.mjs` (`task_opened`, `status_changed`, `task_closed`) и `gate.mjs` (`gate_result`) —
    **отдельным процессом** и best-effort: сбой журнала не имеет права помешать ни смене
    статуса, ни вердикту приёмки, поэтому не `import`, а `spawnSync` в `try/catch`. Формат
    строки — `{"ts":…,"task_id":…,"event":…,"payload":{…}}`, четыре ключа всегда и в этом
    порядке, `ts` в UTC (ISO-8601 с миллисекундами). Посмотреть последние записи:
    `node .claude/hooks/events.mjs --selftest` — читает хвост 64 КБ и печатает строки через ту
    же очистку, что чистит значения. Журнал — рубеж видимости, а не доказательство: правила
    `deny` закрывают по нему `Write`/`Edit`, но не `Bash`;
  - `.claude/hooks/task.mjs` — жизненный цикл задач: `new` (заводит `tasks/<id>/` и кладёт
    туда формы из `assets/stubs`), `status`, `log`, `close`, `list`, `path`.
    `status reworking` увеличивает `review_iterations` в `STATE.md` — **только на входе
    в статус**, повторный вызов счётчик не двигает, — и **отказывает с кодом 3**, когда
    лимит 3 исчерпан или поле не разобрано (мусор, дробное, отрицательное, пустое).
    Отказ происходит до какой-либо записи: ни счётчика, ни статуса, ни журнала, ни события.
    Ограничитель автоматической петли доработки живёт здесь, в коде, а не в тексте промта.
    `list` показывает `ревью: N/3` у задач, которые уже возвращались. `taskDir()`
    проверяет форму id и границу каталога — за `.claude/tasks/` хук не выходит. `list`
    показывает состояние приёмки только при совпадении `task_id` с тем, на который взведён
    гейт: приёмка меряет рабочее дерево, а не задачу, и приписывать чужой вердикт задаче
    значило бы врать. В `allow` лежат только формы без свободного текста (`list`, `path`,
    `close` и восемь статусов поимённо); `new` и `log` несут произвольную строку и спрашивают
    человека намеренно;
  - `.claude/hooks/migrate-tasks.mjs` — перенос памяти копий до 1.10: `artifacts/PLAN.md`
    и `artifacts/history/*` раскладываются по папкам `tasks/<id>/`. Режимы `--plan`
    (предпросмотр) и `--apply`. **Копирует и никогда не удаляет** — отката у операции нет,
    поэтому `--apply` намеренно не в `allow`;
  - `.claude/hooks/archive-task.mjs` — **заглушка**, оставленная ради развёрнутых копий
    1.5.0–1.9.x: их цепочки зовут этот скрипт первым шагом, и его исчезновение сломало бы им
    работу. Ничего не архивирует. Новые цепочки его не вызывают: с 1.10.0 каждая задача живёт
    в своей папке `tasks/<id>/`, и уносить в историю нечего;
  - `.claude/hooks/stats.mjs` — статистика по токенам, моделям и инструментам. Читает
    транскрипты Claude Code из `~/.claude/projects/<кодированный-путь>/*.jsonl` — **формат
    недокументирован**, поэтому скрипт обязан не падать, а честно сообщать, что данных нет;
  - `.claude/hooks/banner.mjs` — три вида приветствия: ASCII для терминала (установщики),
    компактная строка для SessionStart-хука и `--welcome` — markdown с настоящей картинкой,
    который помощник вставляет в свой ответ;
  - `.claude/WELCOME.md` — текст окна приветствия с подстановками `{{LOGO}}`, `{{VERSION}}`,
    `{{AGENTS}}`, `{{COMMANDS}}`, `{{PROFILE}}`, `{{NEXT}}`; витрина, а не логика —
    правится свободно;
  - `.claude/assets/logo.txt` и `logo-mini.txt` — логотип текстом, полный и узкий;
    подменяются без правки кода. В приветствии всегда полный знак (блок кода прокручивается),
    в терминале — по ширине окна: полный → `logo-mini.txt` → первый блок полного →
    одна строка с названием;
  - `.claude/VERSION` — версия набора, **единственное место хранения**;
  - `.claude/settings.json` — права и регистрация хуков;
  - `.claude/artifacts/` — рабочие файлы **приёмки и проекта**: `VERIFY.json` (снимок прогона),
    `VERIFY.lock` (подтверждение набора команд), `GATE_STATE.json` (состояние гейта),
    `events.jsonl` (машинный журнал: только дописывание, рождается при первом событии),
    `ROADMAP.md`, `COMMIT_PLAN.md` и форма `FAQ_TEMPLATE.md`. Форм `PLAN.md`, `REVIEW.md`
    и `SECURITY.md` здесь нет: они лежат в `assets/stubs/` и копируются в каждую задачу
    хуком `task.mjs new`. Из мастер-копии в проект едут **только** заглушки `stubs.mjs`
    (`artifacts/FAQ_TEMPLATE.md`, `tasks/ACTIVE`, `explores/INDEX.md`); всё прочее
    в `artifacts/`, `tasks/` и `explores/` — память проекта, и `update.mjs` её не доносит
    (`neverShip`);
  - `.claude/tasks/` — **основная память проекта**: указатель `ACTIVE` (одна строка с id
    активной задачи) и папка на задачу — `STATE.md` (состояние конвейера), `PLAN.md`,
    `SECURITY.md`, `REVIEW.md`. `REVIEW.md` начинается с шапки
    `verdict / critical / important / minor` — по ней петля доработки решает, вернуть ли
    задачу исполнителю; старый формат (одно слово `APPROVED` вместо всего файла)
    по-прежнему читается `map.mjs`, потому что в уже заведённых задачах он никуда не делся.
    Задачи не затирают друг друга. Правило Р11: папка считается
    задачей, только если имя проходит `^\d{4}-\d{2}-\d{2}-[a-z0-9][a-z0-9-]*$` **и** внутри
    есть `STATE.md`; всё прочее читатели пропускают молча;
  - `.claude/artifacts/history/` — **legacy**: память копий до 1.10 (планы и ревью завершённых
    задач плюс `INDEX.md`). Хранит то, чего нет в коде, — почему сделали так и что отвергли.
    Читается вторым источником — `explorer` перед разведкой и командой `/cckit_recall`;
    новые задачи сюда не пишутся, перенести старое в `tasks/<id>/` умеет `migrate-tasks.mjs`;
  - `.claude/CLAUDE.md` — инструкции по разработке самого набора; **не распространяется**
    (установщики удаляют, команды разворачивания не копируют);
  - `.claude/PROJECT_PROFILE.template.md` — чистый шаблон профиля. **Этот** файл уезжает
    в проекты под именем `PROJECT_PROFILE.md`, а заполненный профиль репозитория остаётся
    здесь. Меняешь структуру профиля — правь оба файла.
- **Команды по одной на агента:** `cckit_explore`, `cckit_plan`, `cckit_audit`, `cckit_implement`,
  `cckit_review`, `cckit_docs`, `cckit_faq`, `cckit_release`, `cckit_commits` — каждая
  запускает ровно одного агента и останавливается. Добавляешь агента — добавь и команду,
  и строку в таблицу `ORCHESTRATOR_PROMPT.md`.
- **Frontend модули / где UI:** нет.
- **Точки входа:** `install.ps1` / `install.sh` — установка набора в `~/.claude/`.
- **Миграции БД:** нет (БД нет).
- **Куда складываются тесты:** тестов и папки для них нет.

## 4. Конвенции (чтобы агенты не ломали стиль)

- **Именование:**
  - Агенты — `.claude/agents/<kebab-case>.md`; имя файла **обязано совпадать** с полем `name`
    во front-matter.
  - Команды — `.claude/commands/cckit_<действие>.md`; аргумент подставляется через `$ARGUMENTS`.
  - Корневые доки — ВЕРХНИМ регистром (`README.md`, `SETUP.md`, `CUSTOMIZE.md`,
    `PROJECT_PROFILE.md`, `ORCHESTRATOR_PROMPT.md`).
- **Стиль Node-скриптов (`.mjs`):** shebang `#!/usr/bin/env node`; ESM (`import`, не `require`);
  в шапке — блочный JSDoc-комментарий на русском, объясняющий назначение и поведение;
  **только встроенные модули `node:*`, никаких внешних зависимостей**; кроссплатформенность
  обязательна (пути через `node:path`, без shell-специфичных операторов); отсутствие внешнего
  инструмента — не ошибка, а мягкий выход. Комментарии объясняют **почему** так сделано,
  а не пересказывают код.
- **Стиль промтов (агенты/команды):** обращение на «ты» («Ты — исполнитель, …»); разделы `##`;
  явный блок жёстких правил; **специфика проекта не хардкодится** — агент читает её из этого
  файла. Front-matter агента: `name`, `description`, `tools` (через запятую), `model: inherit`.
  Front-matter команды: только `description`.
- **Язык:** вся пользовательская документация и промты — на русском. Исключение —
  `install.ps1` (ASCII-only английский, техническое ограничение).
- **Жёсткие запреты:**
  - **Не добавлять внешних зависимостей** — ни в хуки, ни куда-либо ещё. Набор обязан работать
    сразу после распаковки ZIP.
  - **Не хардкодить домашний путь пользователя** — определять `%USERPROFILE%` / `$HOME`
    в рантайме.
  - **Не хардкодить специфику конкретного проекта в агентов** — только через `PROJECT_PROFILE.md`.
  - **Не вписывать не-ASCII в `install.ps1`.**
  - **Разворачивание всегда additive:** существующие файлы проекта не перезаписывать, всё
    пропущенное громко перечислять в конце.
  - **Не расширять `tools:` агентам без явной нужды** — право менять код есть только у
    `implementer` (см. §5).
  - **Не распространять `settings.local.json`** — ни в `~/.claude/agent-kit/`, ни в проекты.
  - Помнить, что `.claude/**` — распространяемый payload (см. врезку в шапке).
- **Эталонный модуль-образец:**
  - агент — `.claude/agents/implementer.md`;
  - команда — `.claude/commands/cckit_new-project.md`;
  - Node-скрипт — `.claude/hooks/check-syntax.mjs`.

## 5. Права доступа / авторизация

- **Модель:** не RBAC и не ownership. Права здесь — **инструментальные**, в двух слоях:
  1. поле `tools:` во front-matter каждого агента (что агенту вообще доступно);
  2. `permissions.allow` / `permissions.deny` в `.claude/settings.json`.
- **Где проверяется:** обеспечивается самим Claude Code при вызове агента/инструмента.
  `deny` переопределяет `allow` и действует в любом режиме, включая `acceptEdits`.
- **Ловушки:**
  - Право менять прод-код есть **только у `implementer`** (`Read, Write, Edit, Bash`).
    Остальные — read-only или Write только в свои артефакты. Расширение `tools:` у любого
    другого агента ломает главную гарантию конвейера — не делать без решения человека.
  - `defaultMode: acceptEdits` снимает подтверждение правок, но **не снимает** `deny`.
  - `settings.json` читается **при старте** Claude Code: после правки нужен полный перезапуск,
    `/clear` настройки не перечитывает. То же касается новых команд и агентов.
  - `.claude/settings.local.json` создаётся Claude Code автоматически (локальные разрешения
    машины). Он в `.gitignore`, и оба установщика удаляют его из распространяемой копии.
- **Права на задачи (`.claude/tasks/`).** В `allow` — одиннадцать точных строк: `task.mjs list`,
  `path`, `close` и восемь статусов поимённо (`exploring`, `planning`, `awaiting_approval`,
  `implementing`, `reviewing`, `reworking`, `done`, `blocked`). Правило простое: в `allow`
  попадают только команды **без свободного текста** — `new` и `log` несут произвольную строку
  и остаются вне списка. По той же причине снят шаблон `gate.mjs --arm:*`: взвод берёт
  название из активной задачи сам, и аргумента у команды нет. В `deny` — четыре строки:
  `Write`/`Edit` по `.claude/tasks/**/STATE.md` и по `.claude/tasks/ACTIVE`. Это **рубеж
  видимости, а не стена**: `deny` закрывает `Write` и `Edit`, но не `Bash`, — состояние задачи
  меняется командой `task.mjs status`, и правка файла руками становится заметным действием,
  а не обычной работой.
- **Что НЕЛЬЗЯ гейтить общей матрицей ролей:** н/д.
- **Граница «набор ↔ проект пользователя».** Развёрнутый набор живёт внутри чужого
  репозитория, поэтому его файлы не должны туда попадать: команды разворачивания добавляют
  `.claude/` в `.gitignore` проекта, `commit-organizer` обязан их не стейджить, а вынести
  вопросом. Единственный осознанный выход наружу — команда `/cckit_push-with-me`, и даже она
  никогда не включает `settings.local.json`.

## 6. Документация и FAQ

- **Куда `documenter` пишет тех-доки:** отдельной папки `/docs` нет. Действующее распределение:
  - `README.md` — что это и зачем, требования, быстрый старт, таблица команд;

  - `.claude/CUSTOMIZE.md` — настройка конкретного развёрнутого экземпляра.
  Новые тех-доки — в эти файлы. Папку `/docs` заводить только под крупный материал.
- **Конвенция имён документов:** корневые доки — ВЕРХНИМ регистром, `.md`, русский текст.
- **FAQ / база знаний для пользователей:**
  - Отдельной базы знаний **нет**. Её роль выполняют «Быстрый старт» в `README.md`, `SETUP.md`

  - Физически — markdown-файлы в корне репозитория.

## 7. Проверка и деплой (как реально убедиться, что не сломано)

- **Автотесты:** нет.
- **Ручной сценарий проверки** (заменяет автотесты):
  1. `node --check .claude/hooks/check-syntax.mjs` и `node --check .claude/hooks/git-status.mjs`
     — оба скрипта разбираются без ошибок;
  2. `node .claude/hooks/check-syntax.mjs --selftest` — показывает, что доступно на машине;
  2а. `node .claude/hooks/verify.mjs --selftest` — какие проверки настроены в §2 и подтверждён ли
     блок; на новой машине блок этого репозитория подтверждается **один раз** руками:
     `node .claude/hooks/verify.mjs --accept` (команды печатаются до записи подтверждения —
     прочитайте их). Дальше `node .claude/hooks/verify.mjs` реально их прогоняет;
  2б. `node .claude/hooks/gate.mjs --dry` — гейт считает своё решение и печатает его, ничего не
     блокируя; в невзведённом состоянии отвечает «гейт не взведён». **Сам гейт живьём проверяется
     только на развёрнутой копии** (см. ниже): красный путь, `--arm`, три попытки и блокировку
     хода в этой папке гонять бессмысленно — здесь набор сам себя не обслуживает;
  3. проверка на битом файле: создать временный файл с заведомо сломанным синтаксисом и скормить
     хуку — `echo '{"tool_input":{"file_path":"<АБСОЛЮТНЫЙ путь>"}}' | node .claude/hooks/check-syntax.mjs`;
     ожидание — текст ошибки и код возврата **2**. Путь обязательно нативный для ОС
     (на Windows `C:/…`, а не `/c/…`), иначе хук просто не найдёт файл и промолчит;
  4. прогнать `install.ps1` / `install.sh` → проверить, что появились `~/.claude/agent-kit/`
     (без `settings.local.json`) и `~/.claude/commands/cckit_{new-project,install,help}.md`;
  5. **полностью перезапустить Claude Code** → в произвольной папке проверить, что видны три
     глобальные команды;
  6. развернуть набор в тестовую папку (`/cckit_new-project probe`) → убедиться, что видны
     команды и девять агентов;
  7. задачи: `node .claude/hooks/task.mjs list` показывает задачи и активную из них,
     `node .claude/hooks/task.mjs path` печатает путь активной. Перенос старой истории
     проверяется **на стенде, а не здесь**: `node .claude/hooks/migrate-tasks.mjs --plan`
     показывает предпросмотр, оригиналы остаются на месте (хук копирует и не удаляет).
- **Как проверяется корректность:** только ручным сценарием выше. Правки в `.claude/**`
  проверяются не «в этой папке», а на **развёрнутой копии** в тестовом проекте — здесь набор
  сам себя не обслуживает.
- **Слепая зона свежести приёмки:** `verify.mjs --fresh` считает отпечаток дерева по git, поэтому
  правки в **игнорируемых** путях свежесть приёмки не сбрасывают. В проекте пользователя это весь
  `.claude/**`, а в этом репозитории — наоборот, `.claude/**` отслеживается. Не переноси вывод из
  одного случая в другой.
- **Порядок деплоя:**
  1. изменить файлы в `claude-agent-kit/`;
  2. заново запустить `install.ps1` / `install.sh` (обновляет `~/.claude/agent-kit/`);
  3. полностью перезапустить Claude Code;
  4. в **уже развёрнутых** проектах файлы не обновляются автоматически — недостающее
     добавляется командой `/cckit_install` (существующее не затирается).
  Распространение — копированием папки (git / архив / носитель). Пуш и публикация — на человеке.

## 8. Git / VCS

- **Remote:** публичный репозиторий на GitHub (`LastArt/claude-agent-kit`, лицензия MIT).
- **Основная ветка:** `main`.
- **Политика push:** push и деплой — **на человеке**, агенты не пушат
  (правило из `ORCHESTRATOR_PROMPT.md`). `commit-organizer` коммитит только локально.
- **Стиль коммитов:** Conventional Commits (`<тип>(<область>): <суть>`), сообщения на русском,
  одна логическая правка на коммит. Типы: `feat`, `fix`, `docs`, `refactor`, `chore`.
- **Что не коммитим:** `.claude/settings.local.json` (локальные разрешения машины), а также
  `.claude/artifacts/`, `.claude/explores/` и `.claude/tasks/` — рабочие файлы конвейера
  и память проекта; все они в `.gitignore`. Перед коммитом убедись, что в правках нет
  абсолютных путей с именем пользователя и машинно-специфичных фактов: этот репозиторий
  публичный.
- **Внимание — асимметрия:** здесь `.claude/` коммитится, потому что это продукт. В проектах
  пользователей действует обратное правило: набор туда не коммитится вообще (см. §5).
  Правя команды разворачивания и `commit-organizer`, не перепутай эти два случая.

## 9. Секреты под защитой (для settings.json → permissions.deny)

> Файлы, которые агентам нельзя читать/писать. `/cckit_research` переносит этот список в
> `settings.json`. По умолчанию: `.env`, `*.pem`, `*.key`, приватные ключи.

- **Реальных файлов секретов в проекте нет** — ни `.env`, ни ключей, ни токенов.
  Действующие правила `deny` в `.claude/settings.json` закрывают на чтение и запись:
  `.env`, `**/.env`, `**/.env.*`, `**/*.pem`, `**/*.key`.
- `.claude/settings.json` — **распространяемый payload**. Любое правило, добавленное «под этот
  репозиторий», протечёт во все проекты, создаваемые набором. Поэтому здесь только универсальные
  запреты; локальные разрешения держи в `.claude/settings.local.json`.
- `.claude/settings.local.json` — не секрет, но и не для распространения: он в `.gitignore`,
  и оба установщика удаляют его из копии, уходящей в `~/.claude/agent-kit/`. Команды
  разворачивания тоже проинструктированы его не копировать.
