# Эталон пользовательской инструкции

## Обязательная структура (порядок фиксирован)

1. **Заголовок** — «Как <что пользователь хочет сделать>»
2. **Кому это нужно** — кто и в какой ситуации (1–2 предложения)
3. **Что понадобится** — доступы и данные, подготовленные заранее (список)
4. **Пошагово** — нумерованный список, один шаг = одно действие
5. **Возможные проблемы** — таблица «симптом → что делать»
6. **Куда обратиться, если не помогло** — куда написать, что приложить

## Скелет

```markdown
# Как <сделать то-то>

## Кому это нужно
<Какой сотрудник и когда этим пользуется.>

## Что понадобится
- Доступ к разделу «<название>» (если его нет — см. последний раздел)
- <Какие данные подготовить заранее>

## Пошагово
1. Откройте раздел «<название>».
2. Нажмите кнопку «<точная подпись кнопки>».
3. Заполните поле «<точное название поля>» — укажите <что>.
4. Нажмите «Сохранить». Появится сообщение «<текст подтверждения>».

## Возможные проблемы
| Что случилось | Что делать |
|---------------|------------|
| Кнопки «<название>» нет на экране | Скорее всего нет доступа. Напишите <кому>. |

## Куда обратиться, если не помогло
Напишите в <канал/человек> и приложите скриншот экрана.
```

## Правила языка

- Пишем конечному пользователю, не технарю: никакого кода, путей, названий функций/таблиц,
  слов «API», «эндпоинт», «токен», «бэкенд».
- Шаги повелительно: «нажмите», «выберите», «введите». Один шаг = одно действие.
- Названия кнопок/пунктов/полей — точно как в интерфейсе, сверять по коду, не выдумывать.
- Одна инструкция = одна задача пользователя.
- Не уверен, как выглядит экран → пометь «⚠️ уточнить» и вынеси вопрос в конец.
