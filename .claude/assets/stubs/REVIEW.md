# REVIEW — <название задачи>

> Файл ведёт агент **reviewer**. Код не правит — только фиксирует замечания.
> Замечаний нет — ставится `verdict: approved` и нули в счётчиках, **а файл остаётся целиком**:
> шапка, соответствие плану, ручной сценарий. Раньше вместо всего файла писалось одно слово
> «одобрено» латиницей; оно ушло, потому что по нему нельзя было отличить «одобрено»
> от «ревью провести невозможно».

**Шапка выше — вход управляющей логики, а не оформление.** По ней петля доработки решает,
вернуть ли задачу исполнителю, поэтому формат жёсткий:

- `---` стоит **первой строкой файла**, выше неё нет ничего — ни пустой строки, ни заголовка;
- блок в файле **ровно один**; `verdict:` где-то ниже закрывающего `---` управляющей логикой
  игнорируется;
- полей четыре: `verdict`, `critical`, `important`, `minor`. Числа обязаны сходиться
  с таблицами замечаний ниже.

**Три вердикта:**

- `approved` — замечаний нет, счётчики нулевые;
- `changes_requested` — есть что исправить. **Любая** тяжесть находок даёт именно его: тяжесть
  выражает шкала 🔴 / 🟡 / ⚪ в таблицах, а не вердикт;
- `blocked` — **ревью невозможно**: нет плана или он нечитаем, предмет ревью не определить.
  Это **не** «нашлось страшное» — страшное всегда `changes_requested`. И это ни статус задачи
  `blocked` (задача остановлена, дальше решает человек), ни остановленная машинная приёмка
  (`GATE_STATE.json`).
