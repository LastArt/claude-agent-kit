# STATE — состояние задачи

> Файл ведёт хук `task.mjs` (`status`, `log`, `close`). Руками его править не нужно:
> статус меняется командой `node .claude/hooks/task.mjs status <статус>`.

**`review_iterations`** — сколько раз ревью возвращало задачу исполнителю. Увеличивает его
`node .claude/hooks/task.mjs status reworking` (только на входе в статус), руками поле
не правится. Потолок — 3, и после него команда **отказывает**, а не предупреждает: дальше
задачу двигает человек.

Единственный законный сброс счётчика — **новая задача**: `task.mjs new` заводит папку
с `review_iterations: 0`. Эта команда несёт свободный текст названия и поэтому лежит **вне**
`permissions.allow`. Незаметно счётчик этим не обнулить: новая задача заводит новую папку
и переставляет указатель `ACTIVE`, то есть след остаётся. Гарантией, что человека непременно
спросят, отсутствие команды в `allow` при этом **не является**. Поведение зафиксировано
намеренно: при следующей правке прав `new` в `allow` не добавлять.

**`class`** — класс риска задачи. Пишет его `node .claude/hooks/task.mjs class`, и значение
равно **большему** из двух: объявленного планировщиком в разделе `## Класс риска` файла
`PLAN.md` и машинного пола по путям, которые план трогает. Понизить итог может только человек
правкой поля руками. Значение `class: -` означает «поля нет, команда не звалась или отказала»,
и все потребители читают его как **`standard`, но не как `cosmetic`**: косметической задача
бывает только по явному `cosmetic` при нулевых замечаниях формы плана.

**`audit_iterations`** — сколько раз план подавался на аудит безопасности. Увеличивает его
`node .claude/hooks/task.mjs status awaiting_approval` и **только на входе** в статус
(`from !== 'awaiting_approval'`), то есть считается подача, а не возврат. Потолок — 3, и после
него команда **отказывает**, а не предупреждает. Сброса нет нигде: ни возвратом в `planning`,
ни обходом через третий статус.

**`stop_kind`** — тип последнего вопроса человеку из закрытого словаря `product` / `technical` /
`security`; ставит его `node .claude/hooks/task.mjs stop <kind>` перед `[СТОП]`. Значение `-`
означает «стопа не было».

Продлить круг аудита может только человек — правкой `audit_iterations` в этом файле руками:
агенту `STATE.md` закрыт правилами `deny` на `Write`/`Edit`.

> Состояния приёмки здесь НЕТ и не будет. Взведён ли гейт, сколько было попыток и чем
> кончился последний прогон — в `.claude/artifacts/GATE_STATE.json`: проверки из блока
> `CCKIT:VERIFY` гоняются по всему рабочему дереву, а дерево одно на все задачи, и дублировать
> машинные факты о приёмке в человекочитаемом файле задачи значило бы заводить вторую правду.
>
> Счётчиков **три**, все до трёх, и они разные. `review_iterations` (здесь) считает возвраты
> на доработку — исчерпан, и задача получает статус `blocked`. `audit_iterations` (здесь же)
> считает подачи плана на аудит — исчерпан, и задача тоже уходит в `blocked`. `attempts`
> в `GATE_STATE.json` считает красные прогоны приёмки — исчерпан, и **останавливается
> приёмка**, а статус задачи гейт не меняет вовсе (он пишет только строку в журнал ниже).

**Статусы (в этом порядке):**
`exploring` → `planning` → `awaiting_approval` → `implementing` → `reviewing` → `reworking`
→ `awaiting_acceptance` → `done` | `blocked`

- `exploring` — идёт разведка, плана ещё нет
- `planning` — пишется план
- `awaiting_approval` — план готов, ждёт человека
- `implementing` — идёт реализация по плану
- `reviewing` — работает ревьюер
- `reworking` — правки по замечаниям ревью; каждый вход сюда — +1 к `review_iterations`
- `awaiting_acceptance` — работа закончена, `DONE.md` написан, ждёт приёмки человеком; вход
  **только** из `reviewing` и только при `verdict: approved` в `REVIEW.md`; взвод гейта при
  входе снимается, **если машинная приёмка это позволяет** (`verified` либо «проверять было
  нечем»), иначе статус меняется, а взвод остаётся — и это видно строкой и в журнале
- `done` — задача закрыта (`task.mjs close`)
- `blocked` — задача остановлена, дальше решает человек: не сошлись три итерации ревью,
  ревью невозможно (`verdict: blocked`) или упёрлись иначе. Не путать с остановленной
  машинной приёмкой
