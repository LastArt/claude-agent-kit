Набор готовых настроек для [Claude Code](https://claude.com/claude-code), который
превращает работу над проектом в управляемый конвейер. Вместо того чтобы один ИИ-ассистент
делал всё сразу — и разбирался в коде, и писал его, и проверял — работа делится между
несколькими агентами с чёткими ролями, а ключевые решения остаются за вами.

## Зачем это нужно

Когда просишь ИИ «сделай функцию», он обычно выполняет всё в одном потоке: изучение,
код, проверку — вперемешку. За таким процессом трудно уследить, легко пропустить ошибку
и сложно остановиться на нужном шаге.

Этот набор разбивает работу на отдельные роли:

- **Исследователь** — только изучает проект и составляет отчёт, код не трогает.
- **Планировщик** — превращает задачу в пошаговый план. Вы утверждаете план до того,
  как что-либо меняется.
- **Аудитор безопасности** — проверяет план на риски **до** реализации: контроль доступа,
  инъекции, утечки данных, секреты. Вы утверждаете план уже с картой рисков.
- **Исполнитель** — вносит изменения строго по утверждённому плану, ничего лишнего.
- **Ревьюер** — проверяет получившиеся изменения: логику, безопасность, крайние случаи.
- **Технический писатель** и **автор инструкций** — оформляют документацию для разработчиков
  и понятные инструкции для пользователей.
- Ещё двое помогают вести журнал изменений и аккуратно раскладывать правки по коммитам.

Вы остаётесь в центре: план и результат проходят через ваше подтверждение, а вносить
изменения в код может только один агент — и только по плану.

## Что для этого нужно

- **[Visual Studio Code](https://code.visualstudio.com/)** — редактор, в котором вы работаете.
- **Расширение Claude Code** для VS Code — через него идёт чат с агентами. Найдите
  «Claude Code» в разделе Extensions и установите; иногда после установки его нужно включить
  вручную.
- **[Node.js](https://nodejs.org/)** — на нём работает проверка синтаксиса, которая ловит
  сломанный код сразу после правки. Без него набор запустится, но эта проверка молча отключится.

Проверить, что Node на месте: `node --version` в терминале.

## Установка (один раз)

1. **Скачайте набор:**
   ```bash
   git clone https://github.com/LastArt/claude-agent-kit.git
   ```
   С GitHub CLI: `gh repo clone LastArt/claude-agent-kit`.
   Без git: кнопка **Code → Download ZIP** и распаковать.

2. **Запустите установщик** из папки набора:
   - **Windows:** двойной щелчок по **`install.bat`**
     _(из терминала: `powershell -ExecutionPolicy Bypass -File .\install.ps1`)_
   - **Linux / macOS:** `bash install.sh`

3. **Полностью перезапустите VS Code** — команды читаются при старте.

Дальше выберите свой случай.

## Новый проект

1. В панели Claude Code: `/cckit_new-project my_own_project`
   Проект появится в `cckit-projects/my_own_project` в домашней папке.
2. Откройте его: **File → Open Folder**.
3. Опишите замысел в `IDEA.md` и выполните `/cckit_research`.
4. Перезапустите VS Code.

## Существующий проект

Работает с любым проектом, независимо от возраста, размера и того, как с ним работали раньше.

1. **Откройте папку проекта** в VS Code.
2. **`/cckit_install`** — добавит только недостающие файлы. Ничего не перезаписывает:
   ваши `CLAUDE.md`, настройки и всё остальное останутся как были, а пропущенное команда
   перечислит в конце.
3. **`/cckit_research`** — вот главный шаг. Набор прочитает ваш код и заполнит
   `.claude/PROJECT_PROFILE.md`: язык и стек, команды сборки и тестов, где что лежит,
   какие в проекте конвенции и где ловушки. Агенти читают этот файл вместо догадок.
4. **Проверьте профиль.** Что набор не смог определить, помечено `TODO` — впишите руками.
   Пять минут здесь экономят часы потом: именно отсюда агенты узнают, какой командой
   гонять тесты и какой модуль брать за образец.
5. **Перезапустите VS Code.**

Файлы набора при этом добавляются в `.gitignore` и не попадают в ваш репозиторий.

## Работа над задачами

`/cckit_feature <что сделать>` — для новых функций, `/cckit_quick <мелочь>` — короткий путь.
Справка по всем командам — `/cckit_help`.

## Обновление

Набор распространяется через GitHub, поэтому обновление идёт в три шага:

1. **Обновите исходник.** В папке, куда клонировали набор, запустите **`update.bat`** (Windows)
   или **`bash update.sh`** (Linux/macOS): скрипт подтянет свежую версию с GitHub (`git pull`)
   и сразу переустановит эталонную копию в `~/.claude/`. Скачивали ZIP вместо `git clone`? —
   скачайте свежий ZIP, распакуйте поверх и запустите установщик.
2. **Перезапустите VS Code** — чтобы подхватились обновлённые команды.
3. **Обновите проекты.** В каждом проекте с набором выполните **`/cckit_update`** — он освежит
   механизм (агентов, хуки, команды), но сохранит ваши настройки, профиль и историю задач,
   а перед перезаписью того, что вы правили сами, спросит. Устаревшие файлы прошлых версий
   предложит убрать.

Убрать набор из проекта — **`/cckit_uninstall`**: на выбор снять только служебные файлы (сохранив
историю прошлых задач) или всё целиком. Перед удалением показывает предпросмотр и трогает только
свои файлы — ваш код и посторонние файлы не заденет.

## Если что-то не работает

| Симптом | Причина |
|---------|---------|
| Команд нет в чате | не запускали установщик или не перезапускали VS Code целиком (`/clear` не помогает) |
| Установка падает на Windows | архив заблокирован: правый клик по ZIP → Свойства → «Разблокировать» → распаковать заново |
| Правки не проверяются на ошибки | не установлен Node.js |

## Команды

Откройте панель Claude Code в VS Code и введите одну из команд.

**Работают в любой папке** (их ставит установщик):

| Команда | Что делает |
|---------|-----------|
| `/cckit_new-project имя` | создаёт новый проект с уже настроенным конвейером |
| `/cckit_install` | добавляет конвейер в уже существующий проект, ничего в нём не затирая |
| `/cckit_update` | обновляет набор в проекте до новой версии, сохраняя ваши правки и наработки |
| `/cckit_uninstall` | аккуратно убирает набор из проекта (на выбор: с памятью или без) |
| `/cckit_help` | справка по всем командам |
| `/cckit_get_instruction` | заново разместить инструкцию на рабочем столе (если потеряли ярлык) |

**Работают только в проекте с развёрнутым набором:**

| Команда | Что делает |
|---------|-----------|
| `/cckit_research` | изучает проект и подстраивает конвейер под его язык, команды и структуру |
| `/cckit_feature задача` | проводит задачу через полный конвейер (для новых функций) |
| `/cckit_quick задача` | лёгкий путь для мелких задач — без полного разбора |
| `/cckit_what_plan` | краткая выжимка текущего плана |
| `/cckit_welcome` | окно приветствия: версия набора и с чего начать |
| `/cckit_recall вопрос` | ищет в истории задач, как и почему что-то делали раньше |
| `/cckit_stats` | статистика: токены, модели, инструменты (`--all` — за всё время) |
| `/cckit_map` | карта проекта: какие модули меняются вместе (страница в браузере) |

**Каждый агент по отдельности** — когда нужен только один шаг:

| Команда | Агент | Что делает |
|---------|----------|-----------|
| `/cckit_explore` | исследователь | разбирается, как устроено, и останавливается |
| `/cckit_explore_parallel A, B` | исследователи веером | по explorer на каждый модуль **параллельно** + сводная выкладка |
| `/cckit_plan` | планировщик | строит план, код не трогает |
| `/cckit_audit` | аудитор безопасности | проверяет план на риски безопасности до реализации |
| `/cckit_implement` | исполнитель | реализует уже утверждённый план |
| `/cckit_review` | ревьюер | проверяет внесённые изменения |
| `/cckit_docs` | технический писатель | документация для разработчиков |
| `/cckit_faq` | автор инструкций | инструкция для пользователей |
| `/cckit_release` | летописец | CHANGELOG и блок «Что нового» |
| `/cckit_commits` | разборщик коммитов | раскладывает правки по коммитам |

### Агенты помнят прошлые задачи

Планы и замечания завершённых задач складываются в `.claude/artifacts/history/`. Там остаётся
то, чего нет в коде: почему сделали именно так, что рассматривали и отвергли, обо что
споткнулись. Исследователь заглядывает туда перед каждой задачей, а спросить напрямую можно
командой `/cckit_recall <вопрос>` — например, «почему отказались от кеша в отчётах».

### Разведка не повторяется дважды

Выкладки исследователя складываются в `.claude/explores/` — по файлу на модуль, с отметкой,
на каком коммите разведка сделана. Задача по тому же модулю начинается с проверки этого кэша:
код с тех пор не менялся — шаг разведки пропускается и работа сразу уходит планировщику;
менялся — исследователь идёт заново и обновляет запись. Кэш наполняет и веерная разведка
`/cckit_explore_parallel`. Сбросить — удалить файл или всю папку: следующая задача просто
разведает модуль с нуля.

### Видно, что с чем связано

`/cckit_map` собирает `.claude/map.html` и открывает её в браузере: значок — папка или файл,
размер — важность (как часто правят и сколько задач через него прошло), линия — их меняли вместе.
Переключатель на странице показывает либо папки (общая картина), либо самые важные файлы; форма
значка говорит про тип файла, цвет — про папку.

Третий уровень — **память**: облако накопленного знания, где узлы это завершённые задачи и
сохранённые разведки, а связь значит «об одном и том же» (общие файлы, общий модуль, общая
тема). Двойной клик по записи открывает её целиком прямо в странице — markdown отрисован как
документ. Удобно вспоминать, почему что-то сделали именно так, не роясь в папках. Серые связи взяты из `git log` (что попадало
в один коммит), оранжевые — из истории задач кита; клик по задаче подсвечивает всё, что она
затронула. Это карта того, **как проект правят на самом деле**, а не схема импортов: разбирать
код набор не пытается, поэтому карта одинаково работает на любом языке. Страница
самодостаточная — данные вшиты внутрь, ни сервера, ни интернета не нужно, файл можно переслать.

### Видно, куда уходит работа

`/cckit_stats` показывает прямо в чате: сколько потрачено токенов, какими моделями, сколько
ушло основному потоку и сколько агентам, какими инструментами работали чаще всего. Данные
берутся из журналов Claude Code на вашем компьютере — сами агенты своего расхода не знают.
Стоимость в деньгах не показывается: она зависит от тарифа.

### Разные модели под разные задачи

План, код и ревью идут на тяжёлой модели — там ошибка дорого стоит. Поиск по коду, описания
и раскладка коммитов — на моделях полегче: быстрее и дешевле без потери качества. Настраивается
одной строкой, см. `.claude/CUSTOMIZE.md`.

### Набор не попадает в ваш репозиторий

Папка `.claude/` добавляется в `.gitignore` проекта: файлы агентов не коммитятся и не
уезжают на удалёнку вместе с вашим кодом.

Поделиться настроенным конвейером с командой — `/cckit_push-with-me`. Команда покажет список
файлов и спросит подтверждение; локальные разрешения не уедут даже так.

Актуальный список всегда можно получить командой `/cckit_help` — она собирает его из файлов
набора, а не из этой таблицы.

Дальше просто ставьте задачи — агенты будут подключаться по очереди, останавливаясь
на моменты, где нужно ваше решение.

По умолчанию Claude Code просит подтвердить каждую правку файла — это защита от случайных
изменений. Если хотите, чтобы правки применялись сразу, нажмите `Shift+Tab`: эта комбинация
на лету переключает режим подтверждений.
